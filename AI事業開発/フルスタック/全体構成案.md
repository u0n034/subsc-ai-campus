Cursor 前提で、**2時間×8コマ＝16時間**の構成案をまとめました。

## 講座コンセプト

* **対象**

  * 非エンジニア〜ライトエンジニア
  * すでに「AI×Web制作（基礎）」「AIによるバックエンド＆DB」レベルはざっくり聞いたことがある人を想定

* **開発スタック（例）**

  * フロント：Next.js / React（TypeScript）
  * バックエンド：Next.js API Routes or Route Handlers
  * DB：PostgreSQL（Supabase などマネージド）
  * ORM：Prisma
  * エディタ：**Cursor**（AIペアプロ前提）

* **ゴール**

  * Cursor を使って、**企画〜設計〜フロント〜バックエンド〜DB〜デプロイまで、一通り通した経験を持つ**
  * 「自分でゼロからは書けないけど、AIにこう指示すればフルスタックアプリを作れる」が体感できる
  * エンジニアと会話できる粒度で、構成・仕様・設計を説明できる

## 各回の詳細構成案（2時間）

### 第1回：企画・全体設計とCursor環境構築（2h）

**狙い：**
「何を作るか」と「どうやって作るか」をAIと一緒に決め、Cursor環境を立ち上げる。

1. 講座のゴール共有（10分）

   * 「16時間で、業務に使えそうなミニ“業務アプリ”を1本」
   * コードを全部理解しようとはせず、「読めるところを増やす」スタンスを共有

2. 作るアプリのテーマ決め（30分）

   * 例：

     * 案件管理／問い合わせ管理
     * 受講生管理
     * 社内タスク管理　など
   * **Cursorへのプロンプト例**

     * 「中小企業の◯◯な業務を楽にする、シンプルなWebアプリの案を3つ出して」
   * 1本に絞り、機能を3〜5個に整理（一覧／登録／更新／検索など）

3. 画面・機能のラフ設計（30分）

   * 必要なページ（例：ログイン／一覧／詳細／編集）
   * 各ページで「何ができるか」を箇条書き
   * AIに「この機能一覧から簡単な画面遷移図をテキストで出して」と依頼

4. Cursorのセットアップ（30分）

   * プロジェクト作成（Next.js + TypeScript）
   * GitHub連携（できれば）
   * Cursor の基本機能紹介：

     * Chat / Composer / 「コードを選択して修正依頼」
   * **AIへの指示の型**
     「この要件で Next.js プロジェクトを初期設定して。package.json と最初のページを提案して」

5. まとめ（20分）

   * 「今日はここまで作りました」確認
   * 次回までにやるとよい任意課題（余裕があれば）

---

### 第2回：データベース＆モデル設計をAIと詰める（2h）

**狙い：**
アプリの“心臓部”となるDB設計を、業務目線＋AIの補助で形にする。

1. エンティティ洗い出し（20分）

   * 第1回で決めたアプリから、

     * 例：Task / User / Project / Status など
   * 「必須情報」と「あったら嬉しい情報」を分ける

2. テーブル・カラム設計（40分）

   * AIにプロンプト：

     * 「この要件を基に、PostgreSQL のテーブル設計案（テーブル名・カラム名・型・説明）を表にして」
   * 不要なカラムを削る／名前を日本語→英語などに整える

3. Prismaスキーマ生成（30分）

   * Cursorに「このテーブル設計から Prisma schema.prisma を生成して」と依頼
   * モデル間のリレーションもAIに提案してもらい、理解ポイントだけ押さえる

4. マイグレーション＆接続確認（20分）

   * Supabaseなどに接続
   * `npx prisma migrate dev` 的な流れをAIに書かせて実行
   * 「とりあえずテーブルはできてそう」を確認

5. まとめ（10分）

   * DB設計の“これだけは押さえておく3ポイント”を復習

---

### 第3回：バックエンドAPIの実装① – CRUDの骨組み（2h）

**狙い：**
バックエンドAPIの「骨だけ」をAIに作ってもらい、読めるようになる。

1. Next.js のAPIルート／Route Handlers のざっくり説明（20分）

   * ファイル構成のイメージ
   * `/api/tasks` などのURLと処理の対応関係

2. 一覧取得APIの実装（40分）

   * AIへの指示例：

     * 「Prisma で tasks を全件取得して JSON で返す Next.js Route Handler を書いて」
   * 実行して、JSON が返ってくることを確認
   * コードの“見るべきポイント”だけ解説（型・関数名・SQLに相当する部分など）

3. 新規作成APIの実装（40分）

   * `POST /api/tasks`
   * リクエストボディのバリデーション（軽く）
   * エラー時のレスポンスもAIに書かせる

4. 今後のCRUDの流れ確認（20分）

   * 更新（PUT / PATCH）・削除（DELETE）のイメージを先に掴んでおく
   * AIに「このAPI設計で CRUD 一覧を書いて」と依頼

---

### 第4回：フロントエンドUIの実装① – 一覧＆登録画面（2h）

**狙い：**
APIとつながった“動く画面”をまず1つ作る。

1. ページ構成の確認（15分）

   * `app/tasks/page.tsx` など
   * 一覧ページに必要な要素を箇条書き

2. 一覧ページの実装（45分）

   * AIに：

     * 「/api/tasks からデータを取得してリスト表示する Next.js のページコンポーネントを書いて」
   * ローディング中表示／エラー表示も追加してもらう

3. 登録フォームの実装（45分）

   * タイトル＋説明など、最低限の項目
   * フォーム送信 → `POST /api/tasks`
   * 成功時：一覧の再読み込み or 追記
   * 失敗時：エラーメッセージ表示

4. 動作確認＆軽いリファクタ（15分）

   * 「最低限、フルスタックっぽく動いている状態」を作る
   * 不要な console.log などをAIに消してもらう

---

### 第5回：フロントエンドUIの実装② – 更新・削除＆UX改善（2h）

**狙い：**
一通りの操作（Create/Read/Update/Delete）と、ちょっと気の利いたUXをAIにやらせる。

1. 更新（編集）機能の実装（50分）

   * 詳細ページ or モーダルどちらか
   * 「ID を指定して1件取得→フォームに初期値セット→保存で更新」流れ
   * AIに「既存コードを元に編集画面を追加して」と頼む

2. 削除機能の実装（30分）

   * 「削除」ボタン → 確認ダイアログ → `DELETE /api/tasks/{id}`
   * 削除後の状態更新（一覧から消す）

3. UXの微改善（30分）

   * 成功時トースト表示
   * ボタンのローディングインジケータ
   * 必須項目のバリデーション

4. 振り返り（10分）

   * 「ここまでで、最低限の業務アプリとして成り立つ」ことを確認

---

### 第6回：認証・認可をAIに実装させる（2h）

**狙い：**
ログイン機能をAIにほぼ丸投げしつつ、「どこで誰が判定されているか」を理解する。

1. 認証のパターンざっくり紹介（20分）

   * Email/Password・OAuth（Googleログインなど）
   * 今回は例として：NextAuth.js など既成ライブラリ利用を想定（名前だけでOK）

2. 認証機能の導入（50分）

   * AIに：

     * 「Next.js + NextAuth でGoogleログインを導入する手順とコードを書いて」
   * 最低限、ログイン／ログアウトボタンが動くところまで

3. 認可（アクセス制御）の導入（30分）

   * 「ログインしていないと /tasks にアクセスできない」
   * API側でも「セッションがないと書き込み不可」にする

4. ユーザーとデータの紐づけ（15分）

   * Task に `userId` を持たせる
   * 「自分のタスクだけ見える」仕様

5. まとめ（5分）

   * セキュリティの深掘りは別講座、ここでは「最低限のライン」を押さえたことを強調

---

### 第7回：テスト・リファクタリング・エラー処理（2h）

**狙い：**
「作って終わり」ではなく、「壊れにくく・読みやすく」する方向に1歩進める。

1. テストの考え方（20分）

   * 単体テスト／結合テストのイメージだけ
   * 「全部を書くのではなく、壊れると困るところだけでも」

2. テストコードをAIに書かせる（40分）

   * 例：

     * 重要なビジネスロジック（期限計算・ステータス変更など）
   * AIに「Jest or Vitest でこの関数のテストを書いて」と依頼
   * テスト実行 → 成功／失敗の見方

3. リファクタリング（30分）

   * 長すぎるコンポーネントの分割
   * 重複コードの関数化
   * Cursorの「Diff表示」「Refactor提案」を活用

4. エラー処理とログ（20分）

   * try/catch の位置
   * サーバー側でのログ出力イメージ
   * AIに「このAPIで想定されるエラーケースと、そのハンドリング方法を列挙して」と依頼

5. まとめ（10分）

   * 「動くだけ」から「運用に耐えそう」へ一歩進んだことを確認

---

### 第8回：デプロイ・運用と「自分用アプリ」への展開（2h）

**狙い：**
実際に外部からアクセスできる状態にして、「ここからどう発展させるか」の道筋を描く。

1. デプロイの流れ説明（20分）

   * Vercel + Supabase を例に
   * GitHub連携で自動デプロイのイメージ

2. AIにデプロイ手順を書かせる（30分）

   * 「このNext.jsアプリをVercelにデプロイする手順を、初心者向けにステップごとに書いて」
   * 実際にデプロイ → URL発行

3. 環境変数・本番設定の確認（30分）

   * DB接続文字列・APIキー等
   * `.env` の扱い方だけ押さえる

4. 「自社用にカスタマイズするなら？」をAIに聞く（30分）

   * 自社業務に合わせたフィールド追加／権限追加／通知機能など
   * 「今後の拡張ロードマップ」をAIに箇条書きさせる

5. クロージング（10分）

   * 16時間で得たものの整理
   * 「次に学ぶなら？」の道（エージェント化／モバイル対応／B2B SaaS化 など）
