AIによるバックエンド開発とデータベース講座

第1回：フロントエンド vs バックエンド

🌟 身近な例から理解する

皆さんが普段使っているWebサービス、スマホアプリ。
これらは全て、「見える部分」と「見えない部分」、つまりフロントエンドとバックエンドの2つで成り立っています。

🛒 Amazon
流れ：
商品を検索 → カートに入れる → 注文ボタンを押す → 確認メールが届く
この一連の流れ、当たり前のように感じていますが、実は「見えている部分」と「見えない部分」に分かれているんです。
🍔 Uber Eats
流れ：
お店を選ぶ → メニューを決める → 注文する → 配達員をリアルタイム追跡
画面に表示されている部分と、裏側で動いている部分がある。
💼 経費精算システム
流れ：
申請を出す → 上司が承認 → 経理が確認 → 振り込まれる
入力画面と、裏側の承認ワークフローに分かれています。

👀 「見える部分」と「見えない部分」

👁️ 見える部分
= フロントエンド
Amazon の場合
  • 商品の写真
  • 価格表示
  • 「カートに入れる」ボタン
  • 検索窓
  • メニューバー
Uber Eats の場合
  • 店舗の一覧
  • 料理の写真
  • カートに追加するボタン
  • 配達先入力フォーム
  • 配達員の現在地マップ
ユーザーが直接触れる、見える部分
🔧 見えない部分
= バックエンド
Amazon の場合
  • 在庫チェック
  • カート情報をデータベースに保存
  • クレジットカード決済処理
  • 注文データの記録
  • 在庫を減らす処理
  • 確認メール自動送信
  • 配送業者システムへの連携
Uber Eats の場合
  • お店に注文を送信
  • 配達員の自動マッチング
  • 決済処理
  • 注文IDの発行
  • GPS位置情報の更新
  • 通知の送信
ユーザーからは見えない裏側の処理

🍽️ レストランで例えると...

この例え、とても分かりやすいですよね!

🏪
フロントエンド = 客席エリア
お客様が直接体験する部分
  • ✓ お客様が座る客席
  • ✓ メニュー
  • ✓ 店内の雰囲気
  • ✓ 接客スタッフ
👨‍🍳
バックエンド = 厨房・バックヤード
お客様からは見えないけれど不可欠な部分
  • ✓ 厨房での調理
  • ✓ 在庫管理
  • ✓ 仕入れ業務
  • ✓ 経理業務

🎨 フロントエンドの役割

ユーザーが直接触れる「見た目」と「操作感」を担当する部分

技術: HTML、CSS、JavaScript を組み合わせて作られています

1
デザインの美しさ
色使い、レイアウト、フォント、余白。

視覚的な要素が洗練されていると、ユーザーは「使いたい」と感じます。

逆に、デザインが古臭かったり、色がバラバラだったりすると、「なんか使いづらそう」と感じてしまいます。
2
使いやすさ (UI/UX)
UI: ユーザーインターフェース
ボタンの配置や画面の構成

UX: ユーザーエクスペリエンス
ユーザーが感じる体験全体

「戻る」ボタンがどこにあるか分かりやすい、エラーメッセージが明確、次に何をすればいいか迷わない。
3
表示速度と操作感
ボタンを押したときに一瞬で反応する、ページの読み込みが速い、スクロールがなめらか。

こういった「サクサク動く感じ」も、フロントエンドの重要な役割です。

いくら見た目が綺麗でも、5秒も待たされたらイライラしますよね。

⚙️ バックエンドの役割

ユーザーからは見えない「裏側の処理」を担当する部分
「接客担当」(フロントエンド) に対して、「厨房や経理や在庫管理を全部やる裏方担当」(バックエンド)

1
データ管理
「誰が」「いつ」「何を」注文したのか。「どの商品が」「何個」在庫として残っているのか。

こういった情報を、全てデータベースに記録し、必要なときに取り出せるようにする。
具体例:
  • Amazonの過去の注文履歴
  • 在庫が残り1個の同時購入制御
  • ユーザーの登録情報の保管
2
ビジネスロジックの実行
ビジネスロジック = 「もし◯◯なら△△する」というビジネス上のルールや判断
ECサイトの例:
  • 在庫が0なら購入ボタンを押せない
  • 合計1万円以上なら送料無料
  • 初回購入者には10%オフ
予約システムの例:
  • 同じ時間帯に複数予約は不可
  • キャンセルは3日前まで
  • 満席なら予約ボタン非表示
3
データベースアクセス
データベースに対して操作を行う部分。専門用語で「CRUD」と言います。
CRUDの4つの操作:
  • Create (作成) - データを保存する
  • Read (読取) - データを取り出す
  • Update (更新) - データを更新する
  • Delete (削除) - データを削除する
複雑な処理の例:
  • 「石川県で購入金額5万円以上の顧客を抽出」
  • 「今年の売上合計を計算」
  • 「各商品の平均評価を算出」
4
外部サービスとの連携
現代のWebシステムは、様々な外部サービスと連携して機能を実現しています。
代表的な外部サービス:
  • 決済: Stripe、PayPal
  • メール配信: SendGrid、Amazon SES
  • SMS送信: Twilio
  • 地図表示: Google Maps API
  • 天気情報、株価情報など

⚠️ なぜバックエンドで処理する必要があるのか？

🔒
セキュリティと正確性の確保
フロントエンドだけで処理すると、改ざんされるリスクがあります。
ブラウザの開発者ツールを使えば、画面上の金額を書き換えることができてしまいます。
🎯 Webシステムの鉄則:
  • フロントエンド: 「ユーザーにとって便利な表示」を担当
  • バックエンド: 「正確な処理と判断」を担当

最終的な判断や計算は、必ずバックエンドで行う
この役割分担が、セキュリティの面でも非常に重要です。

🤖 AIを活用して理解を深める

💡 実際にAIに質問してみよう
質問例:

「Amazonで商品を購入する際、フロントエンドとバックエンドでそれぞれどんな処理が行われていますか? ステップごとにわかりやすく説明してください。」
具体的なサービス名を出して、「ステップごとに」と指定すると、
AIは非常に分かりやすく整理して答えてくれます。

AIは皆さんの「技術コンシェルジュ」として活用できるんです!
🍔
「Uber Eatsで注文から配達までの流れを、フロントエンドとバックエンドに分けて説明してください」
💼
「経費精算システムで、申請から承認、振込までの裏側の処理を教えてください」
📺
「YouTubeで動画を再生するとき、バックエンドではどんな処理が行われていますか?」
🎓 AIを使う際の心構え
  • AIの回答をそのまま鵜呑みにするのではなく、自分の理解を深めるツールとして使う
  • 説明を読んで「なるほど」と理解し、次の疑問を持つ
  • そしてまたAIに聞いてみる
  • この繰り返しが、皆さんの理解を深めていきます

AIは24時間いつでも答えてくれます。何度聞いても嫌な顔をしません。
遠慮せずにどんどん質問して、技術的な理解を深めていってください!
