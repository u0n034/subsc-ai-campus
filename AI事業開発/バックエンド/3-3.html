第3回：SELECTでデータを「読む」体験

📖 SELECT文の基本形

最もシンプルで最も重要なSQL文から始めましょう

SELECT * FROM customers;
📝 日本語で読むと
「customersという表から、全部の列を全部の行分ください」
SELECT
意味：「取り出してください」
データベースに対して「データを取り出したい」という意思表示をする部分。命令の始まりを示す。
*
意味：「すべて」
アスタリスクは「全部」を意味する記号。ここでは「すべてのカラム（列）」を表す。
FROM
意味：「〜から」
どこからデータを取り出すのかを指定する部分。日本語の「から」と同じ使い方。
customers
意味：テーブル名
「顧客テーブル」の名前。取り出し先のテーブルを指定している。

📊 実行結果のイメージ

customer_id name email prefecture created_at
1 山田太郎 yamada@example.com 東京都 2025-11-01
2 佐藤花子 sato@example.com 石川県 2025-11-02
3 鈴木一郎 suzuki@example.com 大阪府 2025-11-03
... すべてのデータが表示される ...
🌟 すべての列を取得
SELECT *
FROM customers;
• すべてのカラムが取得される
• データ量が多い場合は注意
• 確認目的でよく使用
🎯 特定の列だけ取得
SELECT name, email
FROM customers;
• 必要な列だけを指定
• カンマで区切って複数指定
• 効率的なデータ取得
💡 重要なポイント
• IDも一緒に取得する習慣：後の処理でデータを特定するために、主キー（ID）も取得しておくのが基本

• カラム名は正確に：スペルミスがあるとエラーになる。不明な場合はAIに確認

• LIMIT句で件数制限：実務では「SELECT * FROM customers LIMIT 10;」のように、最初の数件だけ取得することが多い

🔍 WHERE句で条件を絞る

「すべてのデータ」ではなく「特定の条件に当てはまるデータだけ」を取得する

SELECT *
FROM customers
WHERE prefecture = '石川県';
📝 日本語で読むと
「customersテーブルから、全部の列を取得する。
ただし、prefectureカラムの値が『石川県』のデータだけに限定して」

⚖️ 比較演算子

=
等しい
!= または <>
等しくない
>
より大きい・より後
<
より小さい・より前
>=
以上
<=
以下

📅 日付・数値での絞り込み例

SELECT *
FROM customers
WHERE created_at >= '2025-11-01';

「2025年11月1日以降に登録されたお客様」を取得
日付は文字列として扱うので、シングルクォーテーションで囲む

SELECT *
FROM orders
WHERE amount >= 10000;

「金額が1万円以上の注文」を取得
数字はシングルクォーテーションで囲まない

🔗 複数条件の組み合わせ

AND（両方とも満たす）
2つの条件を両方とも満たすデータだけを取得
SELECT *
FROM customers
WHERE prefecture = '石川県'
  AND created_at >= '2025-11-01';
「石川県に住んでいて、かつ、11月以降に登録」
OR（どちらか満たす）
2つの条件のどちらか一方を満たせばOK
SELECT *
FROM customers
WHERE prefecture = '石川県'
  OR prefecture = '富山県';
「石川県または富山県のお客様」

🎯 特殊な条件指定

IS NULL / IS NOT NULL
用途：値が入っているか、空欄かをチェック

WHERE email IS NULL
→ メールアドレスが未入力の顧客

WHERE email IS NOT NULL
→ メールアドレスが登録されている顧客
LIKE（部分一致検索）
用途：特定の文字が含まれるデータを検索

WHERE name LIKE '%田中%'
→ 「田中」が含まれる名前
（田中太郎、佐藤田中一郎など）

WHERE name LIKE '田中%'
→ 「田中」で始まる名前
（田中太郎、田中花子など）
💡 WHERE句のポイント
• 文字列はクォーテーションで囲む：'石川県' のように ' で囲む

• 数字は囲まない：10000 のようにそのまま書く

• 日付も文字列扱い：'2025-11-01' のように ' で囲む

• 複雑な条件はAIに依頼：日本語で説明すれば、AIが適切なSQLを返してくれる

📊 ORDER BYで並び替える

取得したデータを、指定した順序で並び替えて表示する

ASC
Ascending（上昇）
昇順
SELECT *
FROM customers
ORDER BY created_at ASC;
小さい値 → 大きい値
古い日付 → 新しい日付
あ → わ（五十音順）
📅 登録日時（古い順）
2025-11-01 ⬆️
2025-11-05
2025-11-10
2025-11-15 ⬇️
DESC
Descending（下降）
降順
SELECT *
FROM customers
ORDER BY created_at DESC;
大きい値 → 小さい値
新しい日付 → 古い日付
わ → あ（逆順）
📅 登録日時（新しい順）
2025-11-15 ⬆️
2025-11-10
2025-11-05
2025-11-01 ⬇️

📝 様々な並び替え例

名前で五十音順
SELECT *
FROM customers
ORDER BY name ASC;
あ行の人が上、わ行の人が下
名簿作成などに便利
複数条件で並び替え
SELECT *
FROM customers
ORDER BY prefecture ASC,
             created_at DESC;
まず都道府県で五十音順
同じ県内では登録日が新しい順
💡 ORDER BYのポイント
• ASCは省略可能：ORDER BY created_at だけでも昇順になる

• DESCは明示が必要：降順にしたい場合は必ずDESCを書く

• 覚え方：「DESCは下降（Descend）、ASCは上昇（Ascend）」

• 試してみる：迷ったら実行してみて、逆だったら入れ替えればOK

🎯 総合例：すべてを組み合わせる

SELECT、WHERE、ORDER BYを組み合わせた実践的なSQL

SELECT customer_id, name, email, created_at
FROM customers
WHERE prefecture = '石川県'
  AND created_at >= '2025-11-01'
ORDER BY created_at DESC;
1 SELECT：取得する列を指定
customer_id、name、email、created_at の4列だけを取得
SELECT customer_id, name, email, created_at
2 FROM：対象テーブルを指定
customersテーブルから取得する
FROM customers
3 WHERE：条件で絞り込む
• prefecture が「石川県」
• かつ（AND）、created_at が「2025年11月1日以降」
→ この2つの条件を両方満たすデータだけに絞り込む
WHERE prefecture = '石川県'
  AND created_at >= '2025-11-01'
4 ORDER BY：並び替える
created_at（登録日）の新しい順に並べる
ORDER BY created_at DESC
🎉 これが読めればSQLの基本は完璧！
「石川県に住んでいて、2025年11月以降に登録したお客様の
ID・名前・メール・登録日を、登録が新しい順に表示する」

このように、SQLの意図を理解できることが最も重要です

🤖 AIを活用したSQL作成

完璧にSQLを書ける必要はありません。AIと協力して使いこなしましょう

💭
1. 要求を日本語で整理
「こういう条件でデータを取りたい」という要求を、日本語で明確にする
🤖
2. AIに依頼
テーブル名、カラム名、条件を伝えて、SQLを書いてもらう
✅
3. 結果を確認・修正
AIが返したSQLの意図を理解し、必要に応じて修正を依頼
💬 AIへのプロンプト例
顧客テーブル customers があり、
prefecture カラムで都道府県、
created_at カラムで登録日を管理しています。

「石川県在住で、2025年10月以降に登録された顧客だけを
取得する SQL」を書いてください。
⬇️ AIの回答 ⬇️
SELECT *
FROM customers
WHERE prefecture = '石川県'
  AND created_at >= '2025-10-01';
💡 AI時代のSQLスキル
• SQLを完璧に書ける必要はない：AIに書いてもらえばいい

• 重要なのは「読めること」：AIが返したSQLの意図を理解できればOK

• 要求を整理する力：「何がしたいか」を日本語で明確にできることが大切

• 結果を評価する力：AIが返したSQLが意図通りかを確認できる

🎯 最も大切なこと プログラミング言語を完璧にマスターする必要はありません。

• AIに適切な指示を出せること
• AIが返してきた結果を評価できること

これが「SQLを書けないけれど、SQLを使いこなせる」という状態です
