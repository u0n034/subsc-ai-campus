第3回：SELECTでデータを「読む」体験

📖 SELECT文の基本形

最もシンプルで最も重要なSQL文から始めましょう

SELECT * FROM customers;
📝 日本語で読むと
「customersという表から、全部の列を全部の行分ください」
SELECT
意味：「取り出してください」
データベースに対して「データを取り出したい」という意思表示をする部分。命令の始まりを示す。
*
意味：「すべて」
アスタリスクは「全部」を意味する記号。ここでは「すべてのカラム（列）」を表す。
FROM
意味：「〜から」
どこからデータを取り出すのかを指定する部分。日本語の「から」と同じ使い方。
customers
意味：テーブル名
「顧客テーブル」の名前。取り出し先のテーブルを指定している。

📊 実行結果のイメージ

customer_id name email prefecture created_at
1 山田太郎 yamada@example.com 東京都 2025-11-01
2 佐藤花子 sato@example.com 石川県 2025-11-02
3 鈴木一郎 suzuki@example.com 大阪府 2025-11-03
... すべてのデータが表示される ...
🌟 すべての列を取得
SELECT *
FROM customers;
• すべてのカラムが取得される
• データ量が多い場合は注意
• 確認目的でよく使用
🎯 特定の列だけ取得
SELECT name, email
FROM customers;
• 必要な列だけを指定
• カンマで区切って複数指定
• 効率的なデータ取得

🆔 実務の鉄則：IDも一緒に取得する

なぜIDが重要なのか？
名前だけでは誰を特定すればいいか分からないことがあります。
「田中太郎」さんは日本中に何人もいるかもしれません。

でも、IDは絶対に重複しない唯一の値なので、確実にその人を特定できます。
これが「主キー」の概念です。
❌ IDなしの場合
SELECT name, email
FROM customers;
取得結果：
田中太郎 | tanaka@example.com
佐藤花子 | sato@example.com
田中太郎 | tanaka2@example.com
⚠️ 同じ名前の人がいる！
どちらの田中太郎さん？
✅ IDありの場合
SELECT customer_id, name, email
FROM customers;
取得結果：
1 | 田中太郎 | tanaka@example.com
2 | 佐藤花子 | sato@example.com
15 | 田中太郎 | tanaka2@example.com
✨ IDで確実に特定できる！
ID=1とID=15で区別可能
📌 実務での使い方
• 後の処理でデータを更新・削除する際に、IDで特定する
• メール送信などの処理でも、IDを使って確実に対象を指定
• リストから詳細画面への遷移でも、IDをパラメータとして渡す
• 「とりあえずIDは取っておく」が実務の鉄則
💡 重要なポイント
• IDも一緒に取得する習慣：後の処理でデータを特定するために、主キー（ID）も取得しておくのが基本

• カラム名は正確に：スペルミスがあるとエラーになる。不明な場合はAIに確認

• LIMIT句で件数制限：実務では「SELECT * FROM customers LIMIT 10;」のように、最初の数件だけ取得することが多い

🔍 WHERE句で条件を絞る

「すべてのデータ」ではなく「特定の条件に当てはまるデータだけ」を取得する

📍 例1：文字列で絞り込む（都道府県）

SELECT *
FROM customers
WHERE prefecture = '石川県';
📝 日本語で読むと
「customersテーブルから、全部の列を取得する。
ただし、prefectureカラムの値が『石川県』のデータだけに限定して」
WHERE
条件を指定する
合図
prefecture = '石川県'
カラム名と値を
イコールで比較
' '
文字列は
シングルクォートで囲む
💡 イメージ
Excelのフィルター機能で「石川県だけ表示」と設定するのと同じ！
東京都、大阪府などのデータは除外され、石川県だけが抽出されます。

📅 例2：日付で絞り込む（登録日）

SELECT *
FROM customers
WHERE created_at >= '2025-11-01';
📝 日本語で読むと
「customersテーブルから全部の列を取得する。
ただし、created_atが2025年11月1日以降のデータだけに限定して」
>= とは？
「以上」という意味
2025年11月1日か、それより後

数学で使う記号と同じです

「今月登録されたお客様」
「最近増えた顧客の傾向」

などの分析によく使います
⚠️ 日付もシングルクォートで囲む
日付は文字列として扱うので '2025-11-01' のように ' で囲みます

🔗 例3：ANDで複数条件（両方とも満たす）

SELECT *
FROM customers
WHERE prefecture = '石川県'
  AND created_at >= '2025-11-01';
📝 日本語で読むと
「石川県に住んでいて、かつ、11月以降に登録したお客様」

2つの条件を両方とも満たすデータだけを取得
🎯 ANDのイメージ（重なる部分だけ）
条件1
石川県
AND
両方とも
条件2
11月以降登録
✅ 取得されるデータ
石川県 AND 11月以降 = 両方を満たす人だけ

🔗 例4：ORで複数条件（どちらか満たす）

SELECT *
FROM customers
WHERE prefecture = '石川県'
  OR prefecture = '富山県';
📝 日本語で読むと
「石川県または富山県のお客様」

2つの条件のどちらか一方を満たせばOK
🎯 ORのイメージ（どちらかに該当すればOK）
条件1
石川県
OR
どちらか
条件2
富山県
✅ 取得されるデータ
石川県 OR 富山県 = どちらかに該当する人全員

🔗 例5：ANDとORの組み合わせ

SELECT *
FROM customers
WHERE (prefecture = '石川県' OR prefecture = '富山県')
  AND created_at >= '2025-11-01';
📝 日本語で読むと
「（石川県または富山県のいずれか）で、
かつ、11月以降に登録したお客様」
💡 カッコの役割
カッコで囲むことで「まず石川県OR富山県を判定 → その結果とAND条件を結合」という順序が明確になります。

複雑な条件になるほどAIに依頼するのが効率的！

🔗 複数条件の組み合わせ

AND（両方とも満たす）
2つの条件を両方とも満たすデータだけを取得

「石川県に住んでいて、かつ、11月以降に登録」

2つの条件のどちらか一方を満たせばOK

FROM customers
WHERE prefecture = '石川県'
  OR prefecture = '富山県';
「石川県または富山県のお客様」

💰 例6：数値で絞り込む（金額）

SELECT *
FROM orders
WHERE amount >= 10000;
📝 日本語で読むと
「ordersテーブルから全部の列を取得する。
ただし、amountが10000以上のデータだけに限定して」

つまり「金額が1万円以上の注文」
❌ 間違い
amount >= '10000'
数字にクォートは不要
✅ 正しい
amount >= 10000
数字はそのまま書く
📌 クォートのルール
• 文字列は ' で囲む： '石川県', 'tanaka@example.com'
• 数字は囲まない： 10000, 25, 100.5
• 日付も文字列扱い： '2025-11-01'

🎯 特殊な条件指定

📧 例7：IS NULL / IS NOT NULL（空欄チェック）

IS NULL（値が入っていない）
SELECT *
FROM customers
WHERE email IS NULL;
📝 意味
「メールアドレスが未入力の顧客」を取得
NULLは「データがない」「未入力」「不明」という状態
IS NOT NULL（値が入っている）
SELECT *
FROM customers
WHERE email IS NOT NULL;
📝 意味
「メールアドレスが登録されている顧客」を取得
データが何か入っている状態
💡 NULLの理解
NULLは「何もない」という特別な状態です。
• 0（ゼロ）とは違います
• 空文字列("")とも違います
• 「値が存在しない」という状態を表します

🔎 例8・9：LIKE（部分一致検索）

部分一致：どこかに含まれる
SELECT *
FROM customers
WHERE name LIKE '%田中%';
📝 意味：「田中」が含まれる名前
✅ ヒットする
田中太郎
✅ ヒットする
田中花子
✅ ヒットする
佐藤田中一郎
% の意味：「何でもいい文字」を表す記号
%田中% = 「前に何か文字があってもOK、後ろに何か文字があってもOK」
前方一致：〜で始まる
SELECT *
FROM customers
WHERE name LIKE '田中%';
📝 意味：「田中」で始まる名前
✅ ヒットする
田中太郎
✅ ヒットする
田中花子
❌ ヒットしない
佐藤田中一郎
田中% の意味：「田中で始まり、後ろに何が続いてもOK」
前に何もついていない「田中」で始まる名前だけが対象
💡 LIKEの使い方
Webサイトの検索ボックスで「キーワード検索」する機能の裏側では、
このLIKE演算子がよく使われています！
💡 WHERE句のポイント
1. WHEREは条件を指定する部分

2. 「カラム名 = 値」という形で条件を書く

3. 文字列は ' で囲む、数字は囲まない

4. 比較演算子 (=, !=, >, <, >=, <=) で様々な条件を表現できる

5. ANDで「両方とも満たす」、ORで「どちらか満たす」条件を作れる

6. IS NULL / IS NOT NULL で未入力チェックができる

7. LIKE で部分一致検索ができる

8. 複雑な条件はAIに日本語で説明して書いてもらえる

📊 ORDER BYで並び替える

取得したデータを、指定した順序で並び替えて表示する

ASC
Ascending（上昇）
昇順
SELECT *
FROM customers
ORDER BY created_at ASC;
小さい値 → 大きい値
古い日付 → 新しい日付
あ → わ（五十音順）
📅 登録日時（古い順）
2025-11-01 ⬆️
2025-11-05
2025-11-10
2025-11-15 ⬇️
DESC
Descending（下降）
降順
SELECT *
FROM customers
ORDER BY created_at DESC;
大きい値 → 小さい値
新しい日付 → 古い日付
わ → あ（逆順）
📅 登録日時（新しい順）
2025-11-15 ⬆️
2025-11-10
2025-11-05
2025-11-01 ⬇️

📝 様々な並び替え例

登録日が新しい順（降順）
SELECT *
FROM customers
ORDER BY created_at DESC;
最近登録された人が上
管理画面で最新情報を見るときに便利
登録日が古い順（昇順）
SELECT *
FROM customers
ORDER BY created_at ASC;
最初に登録された人が上
創業当初からの顧客を確認するときに
ASC省略版
SELECT *
FROM customers
ORDER BY created_at;
ASCは省略可能
書かなくても自動的に昇順になる
名前で五十音順
SELECT *
FROM customers
ORDER BY name ASC;
あ行の人が上、わ行の人が下
名簿作成などに便利
複数条件で並び替え
SELECT *
FROM customers
ORDER BY prefecture ASC, created_at DESC;
まず都道府県で五十音順に並べ、同じ都道府県の中では登録日が新しい順に並べる
都道府県ごとに顧客を見たいが、各都道府県内では新しいお客様を優先的に確認したいときに便利
💡 ORDER BYのポイント
• ASCは省略可能：ORDER BY created_at だけでも昇順になる

• DESCは明示が必要：降順にしたい場合は必ずDESCを書く

• 覚え方：「DESCは下降（Descend）、ASCは上昇（Ascend）」

• 試してみる：迷ったら実行してみて、逆だったら入れ替えればOK

📚 SELECT文の3つの重要な要素

ここまでで、SELECT文の3つの重要な要素を学びました。
この3つを組み合わせることで、データベースから「欲しいデータを、欲しい形で」取り出すことができます。

1️⃣
SELECT と FROM
「どのテーブルから、どの列を取るか」を指定
SELECT customer_id, name, email
FROM customers;
2️⃣
WHERE
「どんな条件で絞り込むか」を指定
WHERE prefecture = '石川県'
  AND created_at >= '2025-11-01'
3️⃣
ORDER BY
「どの順番に並べるか」を指定
ORDER BY created_at DESC;
💡 実務でのSQLの大部分は、この3つの組み合わせ
特殊な関数や高度なテクニックもたくさんありますが、
非エンジニアの方がまず押さえるべきなのは、この3つの基本構造なんです。
🎯 非エンジニアに必要なスキル
✅ 完璧に暗記して自分で書ける必要はありません

重要なのは：

1. 要求を日本語で整理できること
「こういう条件でデータを取りたい」と明確に説明できる

2. AIが書いたSQLを理解できること
「ああ、こういう処理をしているんだな」と読み取れる

🎯 総合例：すべてを組み合わせる

SELECT、WHERE、ORDER BYを組み合わせた実践的なSQL

SELECT customer_id, name, email, created_at
FROM customers
WHERE prefecture = '石川県'
  AND created_at >= '2025-11-01'
ORDER BY created_at DESC;
1 SELECT：取得する列を指定
customer_id、name、email、created_at の4列だけを取得
SELECT customer_id, name, email, created_at
2 FROM：対象テーブルを指定
customersテーブルから取得する
FROM customers
3 WHERE：条件で絞り込む
• prefecture が「石川県」
• かつ（AND）、created_at が「2025年11月1日以降」
→ この2つの条件を両方満たすデータだけに絞り込む
WHERE prefecture = '石川県'
  AND created_at >= '2025-11-01'
4 ORDER BY：並び替える
created_at（登録日）の新しい順に並べる
ORDER BY created_at DESC
🎉 これが読めればSQLの基本は完璧！
「石川県に住んでいて、2025年11月以降に登録したお客様の
ID・名前・メール・登録日を、登録が新しい順に表示する」

このように、SQLの意図を理解できることが最も重要です

🤖 AIを活用したSQL作成

完璧にSQLを書ける必要はありません。AIと協力して使いこなしましょう

💭
1. 要求を日本語で整理
「こういう条件でデータを取りたい」という要求を、日本語で明確にする
🤖
2. AIに依頼
テーブル名、カラム名、条件を伝えて、SQLを書いてもらう
✅
3. 結果を確認・修正
AIが返したSQLの意図を理解し、必要に応じて修正を依頼
💡 AI時代のSQLスキル
• SQLを完璧に書ける必要はない：AIに書いてもらえばいい

• 重要なのは「読めること」：AIが返したSQLの意図を理解できればOK

• 要求を整理する力：「何がしたいか」を日本語で明確にできることが大切

• 結果を評価する力：AIが返したSQLが意図通りかを確認できる
