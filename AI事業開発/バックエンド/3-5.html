AIによるバックエンド開発とデータベース講座

第3回：よくあるエラーとAIに直してもらう流れ

🐛 よくあるエラー例

💡 エラーは敵じゃない！
エラーが出るのは「自分にはできない」という証拠ではありません。
むしろ、「ここがちょっとおかしいですよ」とコンピュータが教えてくれているヒントなんです。

エンジニアでも、何年も経験を積んでいる人でも、
こういったミスは日常茶飯事です。

大切なのは、エラーを恐れずに、「何が原因なのか」を読み解く姿勢です。
パターン 1
カラム名のスペルミス
SELECT *
FROM customers
WHERE prefecturee = '石川県';
ERROR: column "prefecturee" does not exist
原因：
「prefecture」を「prefecturee」と、eを一つ多く書いてしまった

SQLの特徴：
一文字でも違うと、まったく別のものとして認識してしまう
⚠️ 注意点
• 全角/半角の違い
• 大文字/小文字（設定による）
• スペースの有無
パターン 2
クォートの付け忘れ
SELECT *
FROM customers
WHERE prefecture = 石川県;
ERROR: column "石川県" does not exist
原因：
文字列をシングルクォート(')で囲んでいない

データベースの解釈：
「石川県」という文字列ではなく、「石川県」という名前のカラムを探そうとしてしまう
📌 ルール
• 文字列：シングルクォートで囲む
  例: 'Tokyo'
• 数値：そのまま書く
  例: 100
• 日付：文字列として扱う
  例: '2025-11-01'
パターン 3
セミコロンの付け忘れ
SELECT * FROM customers←ここにセミコロンが必要
ERROR: syntax error at or near "SELECT"
(次のSQL文を書こうとした場合)
原因：
命令の終わりを示すセミコロン(;)がない

影響：
データベースが「まだ命令が続くのかな？」と待ち続ける、または複数SQL実行時にエラーになる
💡 習慣化
環境によってはセミコロンなしでも実行できる場合もあるが、
書く習慣を付けておく方が、後々のトラブルを避けられる
🎯 大切なこと
SQLでよく起こるエラーの大半は、こういったタイプミスや記号の抜けです。

エラーメッセージは、一見すると英語ばかりで難しそうに見えますが、
よく見ると「ここがおかしいよ」というヒントが必ず書かれています。

そして、AIに助けてもらえば、このハードルは一気に下がります！

🤖 AIにエラーの意味を聞いてみる

エラーが出たときに、AIにどうやって相談すればいいのか
具体的な流れを見ていきましょう

1
エラーが発生
わざとエラーが出るSQLを書いて実行してみます
SELECT *
FROM customers
WHERE prefecturee = '石川県';
ERROR: column "prefecturee" does not exist
LINE 3: WHERE prefecturee = '石川県';
              ^
エラーメッセージの読み方：
• column "prefecturee" does not exist = prefectureというカラムは存在しない
• LINE 3 = 3行目に問題がある
• ^ マーク = どの部分がおかしいか指し示している
2
SQLとエラーをセットでAIに投げる
エラーメッセージを全部コピーして、AIツールに投げます
💬 AIへのプロンプト例
次のSQLを実行したところ、エラーが出ました。

SQL:
SELECT *
FROM customers
WHERE prefecturee = '石川県';

エラー内容:
ERROR: column "prefecturee" does not exist
LINE 3: WHERE prefecturee = '石川県';
              ^

エラーの意味と、どう直せばいいか教えてください。
ポイント：
SQLとエラー内容の両方をセットで伝えることで、
AIがより的確なアドバイスをしてくれます
3
AIからの回答を読む
AIが原因と修正方法を教えてくれます
🤖 AIの回答
エラーの意味:
「prefecturee」という名前のカラムが存在しないというエラーです。
おそらく、カラム名のスペルが間違っている可能性があります。

修正案:
正しいカラム名は「prefecture」だと思われますので、
次のように修正してください。
SELECT *
FROM customers
WHERE prefecture = '石川県';
確認事項:
もし「prefecture」でもエラーが出る場合は、
テーブル「customers」に実際にどんなカラムがあるのか、
以下のSQLで確認してみてください。
SELECT column_name
FROM information_schema.columns
WHERE table_name = 'customers';
AIの素晴らしいところ：
• エラーの原因を分かりやすく説明
• 修正したSQLまで書いてくれる
• 「それでもダメだったら」という次の手まで提案
• 24時間いつでも、何度聞いても嫌な顔一つしない
4
修正したSQLを実行
AIが提案してくれた修正版のSQLを実行してみます
SELECT *
FROM customers
WHERE prefecture = '石川県';
✅ 成功！エラーが出ず、無事に結果が表示されました

石川県に住んでいる顧客のデータが取得できました
🎉 エラーの原因を突き止めて、正しく修正できました！
このやり方の素晴らしいところは、
自分でSQLの文法を完璧に覚えていなくても大丈夫という点です。

基本的な構造を理解しておくことは大事ですが、
細かいルールやスペルまで全部暗記する必要はありません。

「やりたいこと」を日本語で整理できていれば、
AIがそれをSQLに変換してくれます
⚠️ 注意点：AIも完璧ではない
AIも万能ではありません。時には、間違った提案をしてくることもあります。

大切なこと：
• AIの回答を鵜呑みにせず、実際に試してみる
• うまくいかない場合は、もう一度AIに「これでもダメでした」と伝える
• 何度かやり取りをしながら、正解に近づいていくプロセス

AIとの対話は、一回で終わりではありません！
📚 このセクションのまとめ
1 SQLでよくあるエラーは、「カラム名のスペルミス」「クォートの付け忘れ」「セミコロンの抜け」など、細かいミスがほとんど
2 エラーメッセージは怖くない。「ここがおかしいよ」というヒントが書かれている
3 エラーが出たら、「SQL + エラーメッセージ」をセットでAIに投げる
4 AIが原因と修正方法を教えてくれるので、それを試してみる
5 完璧に覚える必要はなく、AIと一緒に試行錯誤しながら学んでいく
💪 勇気を持ってチャレンジ！ 「AIに助けてもらいながらエラーを直す」という経験を積むことで、
エラーへの恐怖心がなくなり、自信を持ってSQLに向き合えるようになります

ぜひ、動画を見終わった後、実際に手を動かして、
わざとエラーを起こしてみてください。そして、AIに聞いてみてください。

その体験が、あなたのスキルを確実に一段階引き上げてくれるはずです！
