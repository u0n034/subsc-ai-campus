# 講座名
「AIによるバックエンド開発とデータベース」講座

## 全体コンセプト

* **対象**：非エンジニア（バックエンドやデータベースに触れたことがほとんどない人）

* **ゴール**

  * 「バックエンド」「データベース」「API」「SQL」などの基本用語を理解して説明できる
  * AI（ChatGPT等）と一緒に、**簡単なバックエンド＋DB構成のイメージを描ける**
  * 自社の業務データを、**テーブル・カラム・レコード**に分解して考えられる
  * AIにコードを書いてもらいながら、**シンプルなCRUDアプリの流れ**を追える（読める・修正を依頼できる）

* **形式**：2時間 × 8講座（収録のみ／視聴者は動画を見ながら手を動かす想定）

## 各回の詳細構成案（2時間想定）

### 第1回：バックエンドとは？全体像をAIと一緒に掴む（2h）

1. オープニング（10分）

   * この講座のゴール
   * 「エンジニアにはならないけれど、仕組みは理解したい」前提を共有

2. フロントエンド vs バックエンド（25分）

   * 具体例：ECサイト・予約システムなど
   * 「画面側（フロント）」と「裏側の処理（バック）」の分担
   * **AIへの質問例**：「このサービスのバックエンドはどんな仕事をしている？」

3. Webの基本構造（クライアント/サーバー）（25分）

   * ブラウザ→サーバー→データベースの3層イメージ
   * リクエストとレスポンスの流れを図で解説
   * AIに「図解して」とプロンプトするデモ

4. バックエンドの役割まとめ（30分）

   * 認証、処理ロジック、DBアクセス、外部サービス連携
   * **「AI時代のバックエンド」**：コードを書く人だけでなく、設計・ディレクション側も重要

5. ミニワーク（30分）

   * 身近なサービス（例：Uber Eats、予約サイト、社内申請システムなど）を題材に
   * 「フロントで起きていること」「バックエンドで起きていそうなこと」を紙に書く
   * AIに「このサービスの裏側の流れを説明して」と聞くデモ

---

### 第2回：データベースとは？業務データを「表」にしてみる（2h）

1. データベースのイメージ（20分）

   * Excelの表と何が似ていて何が違うか
   * テーブル／レコード／カラムの基本用語

2. 主キーとIDの役割（20分）

   * 「社員番号」「顧客ID」「注文ID」などの具体例
   * 重複しないIDの大切さ
   * AIに「主キーとは何かを小学生にもわかるように説明して」と依頼

3. 業務データのテーブル化ワーク（40分）

   * 例：顧客管理、案件管理、予約管理など
   * 「今はExcelで管理している表」をDB視点で再構成する
   * AIに「このExcelをDBテーブルにすると？」と聞く流れ

4. テーブル同士の関係（ER図の超入門）（30分）

   * 1対多、多対多のイメージ
   * 顧客–注文、社員–部署などの例
   * AIにER図の文章表現を作らせる

5. まとめ＆チェック（10分）

   * 「データベースとはなに？」を一言で言語化してみる

---

### 第3回：SQL入門 – AIに聞きながらデータを「読む・書く」（2h）

1. SQLって何をするもの？（15分）

   * DBに対する「命令文」であることを解説

2. SELECTで「読む」体験（40分）

   * `SELECT * FROM customers;`
   * WHEREで条件検索（「石川県の顧客だけ」「今月登録のユーザー」など）
   * AIに「この条件でSQLを書いて」と依頼 → 実行 → 結果を見る

3. INSERT/UPDATE/DELETEのイメージ（35分）

   * 新規登録 / 更新 / 削除の概念
   * 「消す」のではなく「フラグを立てる」文化も紹介
   * AIに「退会フラグを立てるSQL」を作らせる

4. 典型的なミスの読み方（20分）

   * 文法エラー例・テーブル名の間違い
   * エラーメッセージをAIに貼って「原因を解説して」と聞くデモ

5. まとめ（10分）

   * 非エンジニアとして知っておきたいSQLの使いどころ

---

### 第4回：APIとバックエンドの役割 – HTTPとRESTの超入門（2h）

1. HTTPとは？（20分）

   * URL・メソッド（GET/POSTなど）・ステータスコードのざっくり説明
   * 「404」「500」など身近な例

2. REST APIの基本（40分）

   * エンドポイントとは？
   * `GET /customers`、`POST /orders` などの例
   * AIに「顧客管理システムのAPI一覧を提案して」と依頼

3. JSONというデータ形式（30分）

   * `{ "name": "田中", "age": 35 }` などの例
   * 人が読める／機械も読める形式として理解

4. バックエンドがしていることを言語化（20分）

   * 「APIを受ける → ロジック → DB操作 → 結果返す」の4ステップ

5. ミニワーク（10分）

   * 自社業務の「欲しいAPI」を3つ考えてみる

---

### 第5回：ミニCRUDアプリ① – 要件整理とDB設計をAIとやる（2h）

題材例：
「社内の問い合わせ管理システム」「社内申請管理」「簡易顧客管理」など、ビジネス寄りのテーマ。

1. 要件整理（30分）

   * 誰が使うのか
   * どんな情報を登録／閲覧したいか
   * AIに要件を文章で投げて、整理・補足してもらう

2. エンティティ洗い出し（30分）

   * 問い合わせ、ユーザー、ステータスなど
   * AIに「この業務から必要なテーブル候補を出して」と依頼

3. テーブル設計（40分）

   * 各テーブルのカラム（項目）を決める
   * 主キー、外部キーの関係
   * AIに「テーブル定義書」を作らせる

4. ER図の確認（20分）

   * 人が見て違和感ないかをチェック
   * AIに「この設計の良い点・注意点」を聞く

---

### 第6回：ミニCRUDアプリ② – API設計とAIコード生成を見る（2h）

1. CRUDとは？（15分）

   * Create / Read / Update / Delete の意味を再確認

2. エンドポイント設計（35分）

   * 例：

     * `POST /tickets`（問い合わせを作る）
     * `GET /tickets`（一覧を見る）
     * `PUT /tickets/{id}`（更新する）
   * AIに「このテーブル設計に対応するREST APIを一覧で出して」と依頼

3. AIにバックエンドコードを書かせる（40分）

   * 具体的な言語は軽く触れる程度（例：Python/FastAPI or Node/Express など）
   * 「このAPIを実装するコードを書いて」とプロンプト → ざっと構造を読む
   * 非エンジニアとして押さえておくべき「読み方の視点」を解説

     * URL
     * メソッド
     * どのテーブルを触っているか

4. 動作イメージの確認（20分）

   * 実際の挙動（画面→API→DB）の流れを再度図示
   * AIに「処理フローを言語化して」と頼む

5. まとめ（10分）

   * 「コードが書けなくても、仕様と挙動を理解できれば価値がある」ことを強調

---

### 第7回：運用とセキュリティの基本 – 権限・ログ・バックアップ（2h）

1. ユーザーと権限（30分）

   * 管理者／一般ユーザー／閲覧のみ など
   * RBAC（ロールベース）を言葉だけ紹介
   * AIに「このシステムの権限設計案を出して」と依頼

2. 認証・パスワード・セキュリティの超基礎（30分）

   * パスワードの保存（ハッシュ）・二段階認証の話
   * 情報漏えいリスクのイメージ

3. ログと監査（30分）

   * 「誰が・いつ・何をしたか」を残す重要性
   * 例：更新履歴・アクセスログ
   * AIに「この業務に必要そうなログ項目」を提案させる

4. バックアップと障害対応（20分）

   * 毎日バックアップ／世代管理のイメージ
   * 「DBが壊れたときにどうするか」を非エンジニア目線で理解

5. まとめ（10分）

   * 非エンジニアが「最低限これだけは質問できるようになろう」というチェックリスト

---

### 第8回：自社業務への落とし込み – AIと一緒に「自分用バックエンド構想」（2h）

1. 自社業務の棚卸し（30分）

   * 「紙やExcelでやっている業務」を洗い出す
   * 入力→保管→検索→集計 の流れで整理

2. 業務をDB／バックエンド視点で再構成（40分）

   * エンティティ候補をAIと一緒に出す
   * 必要そうなテーブルと項目を列挙
   * 重複データ・手入力が多い部分を探す

3. 「もしミニシステムを作るなら？」をAIに聞く（30分）

   * テーブル設計案
   * API設計案
   * 非エンジニアが見て理解できる資料にしてもらう

4. マイ設計書の仕上げ（15分）

   * 講座の成果物として「1〜2ページのバックエンド構想メモ」をまとめる

5. クロージング（5分）

   * 次のステップ（エンジニアとの会話・外注・ノーコードツール活用など）にどうつなげるか
