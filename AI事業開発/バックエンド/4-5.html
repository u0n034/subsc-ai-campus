AIによるバックエンド開発とデータベース講座

第4回-5：バックエンドがしていることを4ステップで言語化する

🔄 4ステップモデルの提示

バックエンドがしていることを整理すると...
HTTP、REST API、JSON、SQL...
これまで学んだすべてが、実はこの4つのステップの中に
きれいに整理できる!
1
リクエストを受け取る
フロントエンド(画面側)から「こういう情報が欲しい」「こういうデータを登録したい」というお願いが届く。

このお願いには、URLがあって、HTTPメソッドがあって、場合によってはJSONデータが添付されている。
例:
GET /customers?pref=ishikawa
→ 「石川県の顧客一覧をください」というお願い
2
内容を理解し、ビジネスルールを適用する
受け取ったリクエストの内容を理解して、「このお願いに対して、どう処理すべきか」を判断する。

第1回で学んだ「ビジネスロジック」がここで動く。
チェック項目:
• このメールアドレスは既に登録されていないか?
• 入力された電話番号の形式は正しいか?
• このユーザーには石川県のデータを見る権限があるか?
3
データベースを操作する
第3回で学んだSQLの世界が登場!

ステップ2で判断した内容に基づいて、実際にデータベースに対してSQLを実行する。
SQL例:
顧客一覧を取得なら → SELECT文
新規登録なら → INSERT文
更新なら → UPDATE文
削除なら → DELETE文
4
結果をJSONにまとめて返す
データベースから取得した結果を、フロントエンドが理解できる形、つまりJSONに整形して返す。

HTTPのステータスコードも一緒に返す。
レスポンス例:
成功なら → 200
見つからなければ → 404
エラーなら → 500

💡 具体例で4ステップをなぞる

実際の例で、この4ステップを追いかけてみましょう

GET /customers?pref=ishikawa
「石川県の顧客一覧を取得する」というリクエスト
1
リクエストを受け取る
フロントエンド側(ブラウザやアプリ)から、このリクエストが届きます。

• HTTPメソッド: GET
• パス: /customers
• クエリパラメータ: pref=ishikawa

バックエンドは「顧客リソースに対するGETリクエスト。石川県を指定しているな」と理解します。
2
内容を理解し、ビジネスルールを適用する
受け取った内容を精査します。

• pref=ishikawa というパラメータは有効か?
• 文字列として正しく受け取れているか?
• 都道府県名として認識できる値か?
• このユーザーは顧客データを閲覧する権限を持っているか?

すべて問題なければ、「では、データベースに対して石川県の顧客を取得するクエリを実行しよう」と判断します。

もし何か問題があれば、ここでエラーを返します(403エラー、400エラーなど)。
3
データベースを操作する
第3回で学んだSQLの出番です!

バックエンドは、次のようなSQLを組み立てて実行します。
SELECT * FROM customers WHERE prefecture = '石川県';
データベースはこのクエリを受け取り、customersテーブルの中から、
prefecture列が「石川県」になっているレコードをすべて取り出して返します。

例えば、5件のレコードが該当したとします。データベースからは、5行分のデータが返ってきます。
4
結果をJSONにまとめて返す
データベースから受け取った5件のレコードを、JSON形式に変換します。

今日学んだように、複数のレコードは配列になります。各レコードはオブジェクトです。
[ { "id": 1, "name": "田中太郎", "email": "taro.tanaka@example.com", "prefecture": "石川県" }, { "id": 2, "name": "山田花子", "email": "hanako.yamada@example.com", "prefecture": "石川県" } // ... 以下3件 ]
こういった形のJSONを作り、HTTPステータスコード200(成功)と一緒にフロントエンドに返します。

フロントエンドは、このJSONを受け取って、画面に一覧表示します。

🎯 流れのイメージ

フロント → バックエンド → データベース
↓
データベース → バックエンド → フロント

バックエンドは、その真ん中で、
リクエストを受け取って、判断して、DBとやり取りして、
結果を整形して返す。この4ステップを繰り返している!

🤖 AIに「処理の言語化」をさせるプロンプト例

APIの仕様だけを見ても、「裏側で何が起きているか」は想像しにくい。
そんなとき、AIに聞いてみよう!

📝 プロンプト例
次のAPIが裏側で行っている処理を、 非エンジニアにもわかるように4ステップで説明してください。 API: GET /customers?pref=ishikawa

✨ AIが返してくれるイメージ

「ステップ1では、GETメソッドで/customersへのリクエストを受け取り、クエリパラメータpref=ishikawaを解析します。

ステップ2では、prefパラメータが有効な都道府県名かをチェックし、リクエストユーザーの権限を確認します。

ステップ3では、データベースに対してSELECT文を実行し、石川県の顧客レコードを取得します。

ステップ4では、取得した結果をJSON形式に変換し、ステータスコード200と共にフロントエンドに返します。」
💡 AIを使うメリット
1. コードを読まなくても理解できる
処理の流れを日本語で言語化してもらえる
2. ドキュメントとして保存できる
将来、別の人がシステムを引き継ぐときにも役立つ
3. エンジニアとの会話がスムーズに
「このAPIのステップ2の部分、もう少し詳しく教えてください」といった質問ができる

非エンジニアでも、この4ステップで説明できるようになれば、
システム開発の「共通言語」を持つことができる!
