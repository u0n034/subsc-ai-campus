📄 JSONの基本形を読む

JSONとは何か
JSON = JavaScript Object Notation

「人間が読めて、機械も読める、データの書き方のルール」

データを構造化して表現するための形式

JSONが広まった3つの理由

1
人間が読みやすい
文字で書かれているので、
エンジニアでなくても、
少し慣れれば内容を理解できる
2
機械が処理しやすい
明確なルールがあるので、
プログラムがこれを読み込んで、
自動的にデータとして扱える
3
シンプルで軽量
余計な装飾がなく、
必要最小限の記号だけで構造を表現
ネットワークでの通信に効率的

実際のJSONを見てみましょう

💡 これは何を表しているか?

JSON = テーブルの別の見せ方

JSONの構造を分解する

波括弧 { }
「ここからここまでが1つのまとまりですよ」という印
データベースで言えば、「1レコード」「1行のデータ」を表す
"キー": 値
キー = データベースの「カラム名」「項目名」
値 = その項目の具体的なデータ

例: "name": "田中太郎"
→ 名前という項目の値は田中太郎
カンマ ,
「次にもまだキーと値のペアが続きますよ」という印

⚠️ 最後の行にはカンマを付けない!
これがJSONのルール

JSONのデータ型

📊 数値
"id": 123
引用符なしで書く
整数でも小数でもOK

例: "price": 1980
例: "rating": 4.5
📝 文字列
"name": "田中太郎"
必ずダブルクォーテーションで囲む

人の名前、メールアドレス、住所など、
文字で表現されるデータ
✅ 真偽値
"is_active": true
true = 正しい、有効
false = 間違っている、無効

引用符で囲まない
この2つだけが特別な値

テーブルとJSONの対応

📊 データベースのテーブル
id name email
123 田中太郎 taro@...
≈
📄 JSONの表現
{
  "id": 123,
  "name": "田中太郎",
  "email": "taro@..."
}

📚 配列とネスト – 複数件＆入れ子構造

実際のシステムでは、1件のデータだけを扱うことは稀。
複数のレコードを一度にやり取りすることの方が多い!

📋 配列 = 複数のデータをまとめる
配列(Array) = 「データのリスト」「データの集まり」

角括弧 [ ] で囲む

配列の例

[ { "id": 1, "name": "田中太郎" }, { "id": 2, "name": "佐藤花子" } ]
🔍 構造の読み方
• 全体を囲む 角括弧 [ ] = 「複数のデータのまとまり」
• その中の 波括弧 { } = それぞれ「1行のレコード」
• データ間の カンマ , = 「次にもまだデータが続く」

つまり、角括弧 [ ] は「複数行の表」を表している!

テーブルとの対応

id name
1 田中太郎
2 佐藤花子

↑ この2行のテーブルが、上記のJSONに対応している

ネスト構造 = データの中にデータ

{ "id": 1, "name": "田中太郎", "email": "taro.tanaka@example.com", "orders": [ { "order_id": 101, "product": "ノートPC", "price": 98000 }, { "order_id": 102, "product": "マウス", "price": 2980 } ] }

💡 ネスト構造の理解

顧客の基本情報の中に、"orders"というキーがあり、
その値として配列 [ ]が入っている。

つまり、「注文のリスト」がここに埋め込まれているわけです。

これが「ネスト構造」= データの中に別のデータが入っている状態
