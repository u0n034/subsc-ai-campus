第3回：INSERT / UPDATE / DELETE のイメージ
✨ INSERT
新しい行を追加する

📝 INSERT：新しいデータを追加する

「新しいお客様が登録する」「新しい注文が入る」
こういった場面で使うのがINSERT文です

INSERT INTO customers (name, email, prefecture)
VALUES ('山田太郎', 'taro@example.com', '東京都');
INSERT INTO customers
意味：customersテーブルに挿入する

INTOは「〜の中へ」という意味。
「customersの中に入れる」というニュアンス
(name, email, prefecture)
意味：どのカラムに値を入れるか

「名前、メールアドレス、都道府県の3つの項目に、これから値を入れますよ」と宣言
VALUES
意味：実際に入れる値

VALUESは「値」という意味。
この後ろに実際のデータを順番に並べる
('山田太郎', ...)
意味：具体的なデータ

最初に指定したカラムの順番と対応。
name → '山田太郎'
email → 'taro@example.com'
prefecture → '東京都'
💡 IDの自動採番
多くのデータベースでは、IDは自動的に採番される仕組みになっています。

• customer_id、order_id などの主キーは、データベースが自動で割り振る
• 私たちは「次は123番だな」と計算する必要がない
• INSERT文では、IDを除いた「実際に人間が入力する項目」だけを指定すればOK

つまり、「IDはシステムにお任せ」という感覚で大丈夫です！
🤖 AIを使ったINSERT文の生成
プロンプト例：

顧客テーブルcustomersに、
『鈴木一郎』『ichiro@example.com』『大阪府』という
新規顧客を追加するSQLを書いてください。
⬇️ AIの回答 ⬇️
INSERT INTO customers (name, email, prefecture)
VALUES ('鈴木一郎', 'ichiro@example.com', '大阪府');
日本語で「こういうデータを追加したい」と伝えるだけで、
AIがSQL文に変換してくれます。これが、AI時代のSQL活用です！
🎯 実務での位置づけ
実際のシステムでは、INSERT文を直接実行することは、実はそんなに多くありません。

例：Webサイトで新規会員登録
• ユーザーが名前やメールアドレスを入力
• ボタンを押す
• バックエンドのプログラムが自動的にINSERT文を組み立てて実行

つまり、画面の裏側でこの「INSERT INTO customers」が走っているわけです。

このイメージを持っていると、エンジニアとのコミュニケーションがスムーズになります！
🔄 UPDATE
既存データを更新する

✏️ UPDATE：既存データを書き換える

「メールアドレスを変更したい」「ステータスを更新したい」
既にある行の特定のカラムの値を書き換えるのがUPDATE文です

UPDATE customers
SET email = 'new_mail@example.com'
WHERE customer_id = 123;
UPDATE customers
意味：customersテーブルを更新する

どのテーブルを対象にするかを指定
SET email = '...'
意味：値をセットする

SETは「設定する」という意味。
emailカラムを新しい値に書き換える
WHERE customer_id = 123
意味：どの行を更新するか

これが最重要！
customer_id=123の行「だけ」を更新
⚠️ 鉄則
UPDATEには必ずWHERE句をセットで書く

WHERE句がないと全件書き換わってしまい、
大事故につながります！
⚠️
WHERE句を忘れると大惨事！
WHERE句なしのUPDATE文を実行すると、
テーブルの全顧客データが書き換わってしまいます

全員のメールアドレスが同じになる = 大事故

本番環境では取り返しのつかないことになります

🔍 安全なUPDATEと危険なUPDATEの比較

✅ 安全：WHERE句あり
UPDATE customers
SET email = 'new_mail@example.com'
WHERE customer_id = 123;
結果：
customer_id=123の顧客だけが更新される

影響範囲：1件のみ

これが正しい使い方！
❌ 危険：WHERE句なし
UPDATE customers
SET email = 'new_mail@example.com';
結果：
全顧客のemailが同じ値に書き換わる

影響範囲：全件（数千〜数万件）

絶対にやってはいけない！
📝 複数カラムをまとめて更新
UPDATE customers
SET email = 'new_mail@example.com',
prefecture = '神奈川県',
updated_at = NOW()
WHERE customer_id = 123;

SETの後ろにカンマ区切りで複数の項目を並べることができます。

updated_at = NOW()：更新日時も一緒に記録
→ 「いつ更新されたか」を記録しておくことは実務で非常に重要！

🤖 AIに安全なUPDATE文を書いてもらう
プロンプト例：

顧客テーブルcustomersで、customer_id=456の顧客の都道府県を『北海道』に変更するUPDATE文を書いてください。

WHERE句を必ず含めて、安全に実行できる形でお願いします。
⬇️ AIの回答 ⬇️
UPDATE customers
SET prefecture = '北海道'
WHERE customer_id = 456;
「安全に」「WHERE句必須で」と明示することで、
AIにも「これは慎重に書かなきゃいけないな」と認識させることができます！
🗑️ DELETE
削除と「削除フラグ」の文化

🗑️ DELETE：データを削除する

テーブルから行を消す命令
最も慎重に扱うべき命令です

DELETE FROM customers
WHERE customer_id = 123;
DELETE FROM customers
意味：customersテーブルから削除

文字通り、データを消す命令
WHERE customer_id = 123
意味：どの行を削除するか

WHERE句は絶対に必要！
ないと全データが消えます
☠️
WHERE句なしは事件レベル
DELETE FROM customers;

これを実行すると、
customersテーブルの全データが消えます

全顧客情報が一瞬で消える = もはや事件

会社によっては「本番環境でDELETE文の直接実行を禁止」というルールも

💡 実務では「論理削除」が主流

🔥 物理削除
データを完全に消してしまう方法
一度消したら基本的に元に戻せない
DELETE FROM customers
WHERE customer_id = 123;
❌ デメリット
• データが完全に消える
• 復旧はバックアップからのみ
• 過去データの参照ができない
• 法律的な保管義務に違反する可能性
使用場面：
本当に「もう二度と必要ない」と
確信できる場合だけ
✨ 論理削除（推奨）
データは残しておくけれど、
「削除された」という目印を付ける方法
UPDATE customers
SET is_deleted = 1,
deleted_at = NOW()
WHERE customer_id = 123;
✅ メリット
• データは実際には残っている
• 必要なときに復旧できる
• 過去データの参照が可能
• 削除日時も記録できる
使用場面：
実務では圧倒的にこちらが多い
安全なシステム設計の基本
📊 論理削除の仕組み
1
フラグカラムを用意
is_deleted カラム
• 0 = 有効
• 1 = 削除済み

deleted_at カラム
• 削除日時を記録
2
削除時はフラグを立てる
DELETE文ではなく
UPDATE文を使用

is_deleted = 1 にする
deleted_at に現在日時
3
取得時は条件を追加
SELECT文に
WHERE is_deleted = 0
を必ず追加

削除済みは表示されない
-- 論理削除の実行
UPDATE customers
SET is_deleted = 1, deleted_at = NOW()
WHERE customer_id = 123;

-- 有効な顧客だけを取得
SELECT *
FROM customers
WHERE is_deleted = 0;
💡 論理削除の利点
• 復活が可能：「やっぱり戻したい」という要望にも対応できる

• 過去データの分析：「3年前に削除されたデータ」も参照可能

• 法律対応：一定期間の保管義務がある業種でも安心

• 段階的削除：「削除から1ヶ月後に物理削除」といったルールを設定できる

🤖 AIに安全なSQLを書かせるコツ

AI時代の非エンジニアに求められるスキル

🛡️
ポイント 1
「安全に」を明示する
「WHERE句必須で」
「本番データなので慎重に」
「誤って全件更新にならないように」

こういった一文を添えるだけで、AIの出力が変わる
📋
ポイント 2
テーブル構造を伝える
どんなテーブルがあり、
どんなカラムがあるか

この情報を事前に伝えると、
より正確なSQLを
生成してくれる
👀
ポイント 3
出力を「読む」習慣
AIが返したSQLを
そのまま実行する前に、
一度「読む」

WHERE句の有無、
カラム名の確認だけでも
事故を防げる
💬 安全性を意識したプロンプト例
顧客テーブルcustomersがあります。
本番データなので、誤って全件更新や削除にならないように、
WHERE句を必ず付けたUPDATE文とDELETE文の例を、それぞれ1つずつ示してください。
また、それぞれのSQLの意図も日本語で説明してください。
⬇️ AIの回答 ⬇️
-- 特定顧客のメールアドレスを更新
UPDATE customers
SET email = 'updated@example.com'
WHERE customer_id = 123;

-- 特定顧客を削除
DELETE FROM customers
WHERE customer_id = 456;
+ それぞれに「このSQLは、customer_idが123の顧客のみを対象としています」といった説明も付きます
🎯 非エンジニアに求められるスキル
✅ SQLを完璧に書けること → 不要！

✅ 求められるスキル：
• 「何がしたいか」を日本語で整理できる
• AIが生成したSQLを、ざっくり読めて、おかしいところに気づける
• WHERE句の有無など、基本的なチェックができる
• エンジニアに「このSQL文でお願いします」とスムーズに伝えられる

これが「SQLを書けないけれど、SQLを使いこなせる」状態です！

📚 データ書き込み系SQLまとめ

INSERT / UPDATE / DELETE の3つの命令
✨
INSERT
役割：新しい行を追加

• 新規顧客登録
• 新規注文
• データを増やす

特徴：
IDは自動採番される
人間が入力する項目だけ指定
🔄
UPDATE
役割：既存の値を書き換え

• メールアドレス変更
• ステータス更新
• データを変える

鉄則：
WHERE句は絶対必須！
ないと全件書き換わる
🗑️
DELETE
役割：行を削除

• 物理削除：完全に消す
• 論理削除：フラグを立てる（推奨）

実務：
論理削除が主流
is_deleted フラグで管理
🎯 覚えておくべきこと 皆さんに求められるのは、「SQLを暗記すること」ではありません

重要なのは：
• 「こういう操作がしたい」という要求を日本語でAIに伝えられる
• AIが生成したSQLがどういう動きをするか、ざっくりイメージできる
• WHERE句があるか、更新対象は正しいか、といった基本チェックができる

それだけで、非エンジニアでも十分にSQLを活用できます！
