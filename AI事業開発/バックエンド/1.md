### 2. フロントエンド vs バックエンド（25分）

**目的：** 目に見える部分と見えない部分の役割分担を理解する

**2-1. 身近な例から理解する**（8分）
- **画面表示：3つの具体例**
  - Amazon（商品検索→カート→注文→確認メール）
  - Uber Eats（店選び→注文→配達追跡）
  - 社内経費精算システム（申請→承認→振込）
  
- **「見えている部分」と「見えない部分」を分解**
  - 画面上で実際に見せながら：
    - 「このボタン、この入力フォーム＝フロントエンド」
    - 「在庫の確認、決済、データ保存＝バックエンド」
  - 「皆さんが普段使っているサービスも、この2つで成り立っています」

**2-2. フロントエンドの役割**（6分）
- **定義と特徴**
  - ユーザーが直接触れる「見た目」と「操作感」
  - ボタン、フォーム、メニュー、アニメーション
  - HTML/CSS/JavaScriptで作られている（用語だけ紹介）
  
- **重視される点**
  - デザインの美しさ
  - 使いやすさ（UI/UX）
  - 表示速度、スムーズな操作感

- **画面例を見せながら**
  - 「この部分がフロントエンド」と具体的に指し示す

**2-3. バックエンドの役割**（8分）
- **定義と特徴**
  - ユーザーから見えない「裏側の処理」
  - データの保存・取得・計算
  - ビジネスルールの実行
  - セキュリティの管理
  
- **具体的な仕事内容**
  1. **データ管理**：「誰が」「いつ」「何を」注文したか記録
  2. **ビジネスロジック**：「在庫0なら購入不可」「クーポン適用条件」など
  3. **認証・セキュリティ**：パスワード確認、権限チェック
  4. **外部連携**：決済サービス、メール送信、配送業者API

- **比喩で理解**
  - レストランに例えると：
    - フロントエンド＝接客スタッフ、メニュー、店内の雰囲気
    - バックエンド＝厨房、在庫管理、仕入れ、経理

**2-4. AIに質問してみる実演**（3分）
- **画面録画で実演**
  - ChatGPTまたはClaudeを開く
  - 実際に質問を入力する様子を見せる
  
- **プロンプト例**：
  ```
  Amazonで商品を購入する際、フロントエンドとバックエンドで
  それぞれどんな処理が行われていますか？
  ステップごとにわかりやすく説明してください。
  ```
  
- **AIの回答を表示**
  - 重要なポイントに蛍光ペンでハイライト
  - 「このようにAIに聞くことで、技術的な仕組みを理解できます」
  - 「皆さんも動画を止めて、実際に試してみてください」

### 3. Webの基本構造（クライアント/サーバー/データベース）（25分）

**目的：** リクエスト→処理→レスポンスの流れを視覚的に理解する

**3-1. 3層構造の全体像**（10分）
- **図解を中心に説明**
  - 画面に大きく3層の図を表示
  
- **各層の役割**

  **①クライアント（ブラウザ・スマホアプリ）**
  - ユーザーが操作する場所
  - 「データをください」「これを保存して」とお願いする側
  - 例：Chrome、Safari、スマホアプリ
  
  **②サーバー（バックエンド）**
  - リクエストを受けて処理する場所
  - 「わかりました、処理します」と応える側
  - 判断や計算をする「頭脳」の役割
  
  **③データベース**
  - データを保管しておく場所
  - サーバーからの指示で、データを出し入れ
  - 「図書館の書庫」のようなイメージ

- **関係性の強調**
  - 「クライアントとデータベースは直接やり取りしません」
  - 「必ずサーバー（バックエンド）を経由します」
  - 「これがセキュリティ上も重要なポイントです」

**3-2. 具体的な処理の流れを追う**（12分）

**例①：ログインの流れ**（6分）
- **画面にステップを表示しながら説明**
  1. ユーザーがメールアドレスとパスワードを入力（クライアント）
  2. 「ログインボタン」をクリック
  3. クライアント→サーバーへリクエスト送信
  4. サーバーがデータベースに「このユーザー情報ある？」と問い合わせ
  5. データベースが該当ユーザーのデータを返す
  6. サーバーがパスワードを照合（ハッシュ化されたもの同士で比較）
  7. 結果を「ログイン成功」としてクライアントに返す（レスポンス）
  8. 画面がマイページに切り替わる

- **アニメーションまたは図で視覚化**
  - 矢印で情報の流れを示す
  - 各ステップで何が起きているか明示

**例②：商品検索の流れ**（6分）
- **画面にステップを表示**
  1. ユーザーが「ノートパソコン」と検索窓に入力
  2. クライアント→サーバーへ検索リクエスト
  3. サーバーがデータベースに「"ノートパソコン"を含む商品を全て取得」と指示
  4. データベースが該当する商品リスト（数百〜数千件）を返す
  5. サーバーが並び替え（人気順、価格順など）や絞り込み
  6. 結果をクライアントに返す
  7. 画面に検索結果が表示される

- **補足説明**
  - 「検索結果が一瞬で表示されるのは、データベースとサーバーの処理が高速だから」
  - 「この裏側の処理がバックエンドの仕事です」

**3-3. AIで図解してもらう実演**（3分）
- **実際の操作を画面録画**
  - AIツールを開く
  
- **プロンプト例**：
  ```
  ECサイトで商品をカートに入れる処理について、
  クライアント・サーバー・データベースの3層で処理の流れを
  図解してください。Mermaid記法で出力してください。
  ```
  
- **AIが生成した図を表示**
  - Mermaidプレビューツールで図を表示
  - 「このように、AIは処理の流れを図にしてくれます」
  - 「複雑な仕組みも、可視化すると理解しやすくなります」
  - 「皆さんも気になるサービスで試してみてください」

### 4. バックエンドの役割まとめ（30分）

**目的：** バックエンドが担う主要機能を体系的に整理する

**4-1. バックエンドの4大機能**（18分）

**導入**（1分）
- 「バックエンドは具体的に何をしているのか、4つに分けて見ていきましょう」

**①認証・認可（Authentication & Authorization）**（4分）
- **認証とは**：「あなたは本当に本人ですか？」の確認
  - ログイン時のパスワードチェック
  - 二段階認証（SMSコード入力など）
  
- **認可とは**：「あなたは何ができますか？」の判断
  - 管理者だけが削除できる
  - 自分が作成した記事だけ編集できる
  - 有料会員だけが見られるコンテンツ

- **なぜ重要か**
  - セキュリティの要
  - 情報漏えい防止

**②ビジネスロジック（Business Logic）**（5分）
- **定義**：「もし◯◯なら△△する」というルール・判断
  
- **具体例**
  - ECサイト：「在庫が0なら購入ボタンを非表示」「合計金額が1万円以上で送料無料」
  - 予約システム：「同じ時間に複数予約は不可」「キャンセルは3日前まで」
  - ポイントシステム：「購入金額の5%をポイント付与」「誕生月は10%」

- **なぜバックエンドで処理？**
  - フロントだけだと改ざんされるリスク
  - 「ブラウザで金額を書き換える」などの不正を防ぐ
  - 正確な計算と判断はサーバー側で

**③データベースアクセス（Database Access）**（4分）
- **CRUDという概念**（次回詳しく）
  - Create（作成）：新規データ登録
  - Read（読取）：データ検索・取得
  - Update（更新）：既存データ修正
  - Delete（削除）：データ削除

- **複雑な処理の例**
  - 複数のテーブルを結合して検索
  - 集計（売上合計、平均値など）
  - 条件に合うデータだけ抽出

**④外部サービス連携（External API Integration）**（4分）
- **代表例**
  - 決済サービス（Stripe、PayPal）
  - メール配信（SendGrid）
  - SMS送信（Twilio）
  - 地図・位置情報（Google Maps API）
  - 天気情報、株価情報

- **なぜバックエンドで連携？**
  - APIキー（秘密の認証情報）を隠すため
  - セキュリティ上、クライアント側に置けない
  - 処理の一貫性を保つため

**4-2. AI時代のバックエンドの捉え方**（10分）

**従来の状況**（3分）
- バックエンド＝プログラマーの専門領域
- コードが書けないと何もできない
- 非エンジニアは「お願いする」だけの立場

**これからの変化**（4分）
- **AIがコードを書く時代**
  - ChatGPT、GitHub Copilot、Cursorなど
  - 要件を伝えれば、コードを生成してくれる
  
- **求められる人材の変化**
  - コードを書ける人→引き続き重要
  - **新たに価値が出る人**：
    - 「何を作るべきか」を言語化できる人
    - 「こういう処理が必要」を構造化できる人
    - AIが生成したコードを評価・修正指示できる人
    - エンジニアと円滑にコミュニケーションできる人

**AIディレクターの役割**（3分）
- **要件定義**：「こういうシステムが欲しい」を明確に
- **設計支援**：「この機能には、こういうデータとロジックが必要」
- **AIへの指示**：適切なプロンプトで、欲しいアウトプットを引き出す
- **評価と修正**：「ここはもっとこうしたい」と改善指示
- **エンジニアとの橋渡し**：技術的な会話ができる

- **この講座のゴール**
  - 「皆さんをAIディレクターとして活躍できる人材に育てます」

**4-3. ここまでのまとめ**（2分）
- バックエンドは「見えない部分」だが「システムの心臓」
- 4つの主要機能を理解しておけば、全体像が掴める
- AI時代は、コードが書けなくてもバックエンドに関われる

7. **通知送信**：
   - 「注文確定」「調理開始」「配達中」などのプッシュ通知
   - メール送信
8. **評価・レビュー機能**：
   - 配達完了後の評価データ保存
   - 平均評価の再計算

  - 「特に配達員の位置情報は、リアルタイム処理の代表例」
