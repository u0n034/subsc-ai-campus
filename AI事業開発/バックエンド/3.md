### 3. SELECTでデータを「読む」体験（40分）

**目的：** SELECT文の基本構造と、WHERE・ORDER BYなどのよく使う句のイメージを掴む

> 想定：シンプルな `customers` テーブルを例に画面共有
> （第2回で出てきた顧客テーブルを再利用するとスムーズ）

#### 3-1. SELECT文の基本形（10分）

* スライドにシンプルな例：

  ```sql
  SELECT * FROM customers;
  ```

* 読み方を分解：

  * `SELECT` … 取り出す
  * `*` … すべてのカラム
  * `FROM customers` … customersテーブルから

* ナレーション：

  * 「“customersという表から、全部の列を全部の行分ください”という意味です」
  * 「**“日本語 → SQL”に翻訳しているだけ**と捉えてください」

* 別パターン：

  ```sql
  SELECT name, email
  FROM customers;
  ```

  * 「名前とメールだけ欲しいときは、**欲しい項目だけ並べる**」

#### 3-2. WHEREで条件を絞る（15分）

* 例1：都道府県で絞る

  ```sql
  SELECT *
  FROM customers
  WHERE prefecture = '石川県';
  ```

  * 「石川県のお客さまだけ欲しいとき」

* 例2：日付で絞る（登録日が今月の顧客）

  ```sql
  SELECT *
  FROM customers
  WHERE created_at >= '2025-11-01';
  ```

* ナレーション：

  * 「WHEREは、“こんな条件の行だけください”というフィルター」
  * 「Excelのフィルター機能や、行の抽出イメージに近いです」

* よく使う比較演算を簡単に：

  * `=`（等しい）、`!=` or `<>`（等しくない）
  * `>` / `<` / `>=` / `<=`
  * `AND` / `OR` で条件を組み合わせる

* AIへの依頼例（画面で実演）：

  ```text
  顧客テーブル customers があり、
  prefecture カラムで都道府県、
  created_at カラムで登録日を管理しています。

  「石川県在住で、2025年10月以降に登録された顧客だけを
  取得する SQL」を書いてください。
  ```

* 実際にAIが返したSQLを読み上げながら、

  * 日本語 → SQL の対応関係をなぞる

#### 3-3. ORDER BYで並び替える（10分）

* 例1：登録日が新しい順に並び替え

  ```sql
  SELECT *
  FROM customers
  ORDER BY created_at DESC;
  ```

* 例2：名前の50音順（昇順）

  ```sql
  SELECT *
  FROM customers
  ORDER BY name ASC;
  ```

* ナレーション：

  * 「`ORDER BY` は“並び替えのルール”」
  * 「`ASC` は昇順、`DESC` は降順。
    迷ったら、“A（小さい）からD（大きい）へ”くらいの感覚でもOKです」

* AIプロンプト例：

  ```text
  顧客テーブル customers から、
  石川県の顧客だけを取得し、
  created_at（登録日）の新しい順に並べる SQL を書いてください。
  ```

* まとめコメント：

  * 「ここまでで、`SELECT / FROM / WHERE / ORDER BY` という
    “よく見る4点セット”のイメージが掴めれば十分です」

### 4. INSERT / UPDATE / DELETE のイメージ（35分）

**目的：** データの「追加／更新／削除」の概念を理解し、実務の“怖さ”も含めてイメージしてもらう

#### 4-1. INSERT：新しい行を追加する（10分）

* 例：新しい顧客を追加

  ```sql
  INSERT INTO customers (name, email, prefecture)
  VALUES ('山田太郎', 'taro@example.com', '東京都');
  ```

* ナレーション：

  * 「`INSERT INTO` は、“この表に、新しい行を1つ入れてください”」
  * 「VALUES のカッコの中に、入れたい値を並べていくイメージ」

* AIに日本語から生成させる例：

  ```text
  顧客テーブル customers に、
  「鈴木一郎」「ichiro@example.com」「大阪府」
  という新規顧客を追加する SQL を書いてください。
  ```

#### 4-2. UPDATE：既存データを更新する（10分）

* 例：メールアドレスの変更

  ```sql
  UPDATE customers
  SET email = 'new_mail@example.com'
  WHERE customer_id = 123;
  ```

* ナレーション：

  * 「UPDATEは、“この条件に当てはまる行の、この項目だけ書き換えてください”」
  * 「`WHERE` を付け忘れると、**全件書き換わって大事故になる**ので要注意です」

* 実務目線でひと言：

  * 「本番環境のDBでは、**基本的に自分でUPDATEを書かない運用**も多いです」
  * 「ただ、UPDATEのイメージを持っておくことで、エンジニアとの会話がかなり楽になります」

#### 4-3. DELETE：削除と「削除フラグ」の文化（10分）

* 例：DELETEの基本形

  ```sql
  DELETE FROM customers
  WHERE customer_id = 123;
  ```

* ナレーション：

  * 「これが“物理削除”と呼ばれるものです」
  * 「一度消してしまうと、基本的には元に戻せません」

* 実務でよくある「削除フラグ」の話：

  * `is_deleted` カラム（0:有効、1:削除扱い）を持たせる

  * 削除するときは、

    ```sql
    UPDATE customers
    SET is_deleted = 1
    WHERE customer_id = 123;
    ```

  * 実際に使うデータ取得のSQLは、

    ```sql
    SELECT *
    FROM customers
    WHERE is_deleted = 0;
    ```

* メッセージ：

  * 「“消す”のが怖いので、**“見えなくする”だけにしておく文化**がある、というイメージを持ってください」

#### 4-4. AIに安全なSQLを書かせるコツ（5分）

* プロンプト例：

  ```text
  顧客テーブル customers があります。
  本番データなので、誤って全件更新や削除にならないように、
  WHERE句を必ず付けた UPDATE 文と DELETE 文の例を、それぞれ1つずつ示してください。
  また、それぞれのSQLの意図も日本語で説明してください。
  ```

* ナレーション：

  * 「**“安全に書いて”と明示すると、AI側もより慎重なSQLを返してくれる**ことが多いです」

### 5. よくあるエラーとAIに直してもらう流れ（15分）

**目的：** エラーにビビらず、「AIにエラー文を貼って相談する」という習慣を持ってもらう

#### 5-1. ありがちなエラー例（7分）

* スライドに典型パターンを表示：

  1. カラム名のスペルミス

     * 例：`prefecture` を `prefecturee` と書いてしまう
  2. シングルクォート抜け
  3. セミコロン `;` を付け忘れる

* エラーメッセージ例：

  * `column "prefecturee" does not exist` など
    → 「“そんなカラムないよ”と言われている」

* ナレーション：

  * 「SQLはちょっとしたタイプミスでもエラーになります」
  * 「**エラーが出るのは“できない”証拠ではなく、“ここがおかしいよ”というヒント**です」

#### 5-2. AIにエラーの意味を聞いてみるデモ（8分）

* 実演イメージ（画面録画）：

  1. わざとカラム名を間違えたSQLを書いて実行 → エラー表示
  2. エラー全文をコピーして、AIに貼り付ける

* プロンプト例：

  ```text
  次のSQLを実行したところ、エラーが出ました。

  SQL:
  SELECT *
  FROM customers
  WHERE prefecturee = '石川県';

  エラー内容:
  column "prefecturee" does not exist

  エラーの意味と、どう直せばいいか教えてください。
  ```

* ナレーション：

  * 「このように、**“SQL + エラー全文”をセットで投げる**と、
    AIがどこがおかしいか、だいたい教えてくれます」
  * 「文法やスペルに囚われすぎず、**“やりたいことの日本語”→“AIにSQL化してもらう”**
    という流れを大事にしてください」
