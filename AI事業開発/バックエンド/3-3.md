# 第3回「3. SELECTでデータを「読む」体験」ナレーション原稿

## 3-1. SELECT文の基本形(10分)

それでは、ここから実際にSQLを使ってデータを読む体験をしていきましょう。今日のメインパートです。

まず、SELECT文の最もシンプルな形からご紹介します。画面に表示しているこちらのSQL文を見てください。

```sql
SELECT * FROM customers;
```

たった一行ですが、これだけでデータベースからデータを取り出すことができます。では、この一行を丁寧に分解して読んでいきましょう。

まず「SELECT」という単語。これは英語で「選ぶ」「取り出す」という意味ですね。データベースに対して「データを取り出したいです」という意思表示をしている部分です。レストランで「注文します」と言うような、命令の始まりだと思ってください。

次に出てくる「アスタリスク」、この星印ですね。これは「すべて」という意味を表す記号です。プログラミングの世界では、アスタリスクは「全部」を意味することが多いんです。ここでは「すべてのカラム」つまり「表のすべての列」を意味しています。

そして「FROM」。これは「〜から」という意味の英単語ですね。まさに日本語と同じ使い方です。「どこから取り出すのか」を指定する部分です。

最後に「customers」。これはテーブルの名前です。前回の講座で出てきた「顧客テーブル」のことですね。英語で「顧客たち」という意味の単語を使っています。

では、この4つのパーツを組み合わせて、もう一度読んでみましょう。

「SELECT」→ 取り出してください
「*」→ すべての列を
「FROM customers」→ customersというテーブルから

つまり、日本語に訳すと「customersという表から、全部の列を全部の行分ください」という意味になるんです。とてもシンプルですよね。

重要なポイントは、SQLというのは結局のところ「日本語をコンピュータ向けの言葉に翻訳しているだけ」だということです。皆さんが「顧客テーブルの全データが見たい」と思ったら、それをこのSQLの形式に変換すればいいだけなんです。

実際にこのSQLを実行すると、どうなるでしょうか。画面に表示されているイメージを見てください。customersテーブルに入っているすべてのデータが、表の形で返ってきます。顧客ID、名前、メールアドレス、住所、登録日時など、テーブルに定義されているすべての項目が、すべての行について表示されるわけです。

もし、このcustomersテーブルに1000件のデータが入っていれば、1000件すべてが返ってきます。10万件入っていれば、10万件すべてが返ってきます。アスタリスクで「全部」と指定したので、当然ですね。

実際、実務でこのSQL を書くときは注意が必要です。なぜなら、本番環境のデータベースには何十万件、何百万件というデータが入っていることも珍しくないからです。そんな状態で「SELECT * FROM customers;」と実行してしまうと、データベースがすべてのデータを読み込もうとして、処理に時間がかかったり、場合によってはシステム全体が重くなったりすることもあります。

ですから、実務でデータを確認したいときは「LIMIT」という句を付けて、最初の数件だけ取得する、という使い方をすることが多いんです。たとえば「SELECT * FROM customers LIMIT 10;」とすれば、最初の10件だけが返ってきます。まあ、これは少し応用的な話なので、今は「ああ、そういう工夫もあるんだな」くらいに思っておいてください。

さて、話を戻しましょう。「全部の列が必要ない」ということもよくあります。たとえば、顧客の名前とメールアドレスだけが知りたい場合。そういうときは、アスタリスクの代わりに、欲しい項目だけを並べることができます。

こちらの例を見てください。

```sql
SELECT name, email
FROM customers;
```

アスタリスクが消えて、代わりに「name」と「email」という2つのカラム名が入りました。カンマで区切って並べているのがわかりますね。

これを日本語で読むと「customersテーブルから、nameとemailの列だけを取り出してください」という意味になります。

このSQLを実行すると、今度は名前とメールアドレスの2列だけが返ってきます。住所も電話番号も登録日時も、すべて省かれた状態で結果が表示されるんです。

このように、SELECTの後ろに書く内容を変えることで「どの列が欲しいか」をコントロールできるわけです。

欲しい列が3つあるなら、カンマで3つ並べればいい。5つあるなら5つ並べる。すべてが欲しいなら、アスタリスクを使う。とてもシンプルなルールです。

ここで大事なのは、カラム名を正確に書くことです。たとえば「name」というカラムがあるのに「names」と複数形で書いてしまったり、「e-mail」と書くべきところを「email」と書いてしまったりすると、データベースは「そんなカラムは存在しません」とエラーを返してきます。

でも、安心してください。もしカラム名がうろ覚えでも、AIに聞けば教えてくれます。「顧客テーブルにはどんなカラムがありますか」と聞くだけでいいんです。あるいは、テーブルの構造を確認する専用のSQLもありますが、それは今は覚えなくて大丈夫です。必要になったときにAIに聞けばいいだけですから。

もう一つ、よく使うパターンをご紹介しましょう。先ほどのSQLに、カラムをもう一つ追加してみます。

```sql
SELECT customer_id, name, email
FROM customers;
```

今度は「customer_id」という顧客IDも含めた3列を取得しています。

実務では、このようにIDも一緒に取得することがとても多いんです。なぜかというと、たとえば「この顧客の情報を更新したい」となったときに、名前だけでは誰を更新すればいいか特定できないことがあるからです。同じ名前の人が複数いるかもしれませんよね。「田中太郎」さんなんて、日本中に何人いることか。

でも、IDは絶対に重複しない唯一の値なので、確実にその人を特定できるんです。前回の講座で「主キー」という概念を学びましたよね。まさにあれです。主キーであるIDがあれば、「この人」を間違いなく特定できる。だから、データを取得するときは「IDも一緒に取っておく」というのが基本的な考え方になります。

特に、取得したデータを元に何か処理をしたいとき、たとえば「このお客様にメールを送りたい」とか「この注文をキャンセルしたい」といったときに、IDがないと後の処理ができなくなってしまいます。ですから、「とりあえずIDは取っておく」というのが実務での鉄則なんです。

さて、ここまでで SELECT文の基本形を理解していただけたと思います。まとめると、

- SELECTは「データを取り出す」命令
- アスタリスクは「全部の列」、または個別にカラム名を指定できる
- FROMの後ろにテーブル名を書く
- これで「どのテーブルから、どの列を取り出すか」を指定できる
- 必要に応じてカラムを選んで指定することで、本当に必要なデータだけを効率的に取得できる

という構造になっているんですね。

これが、SQLの中でも最も基本的で、最もよく使われる形です。これさえ理解できれば、SQLの半分は理解できたと言ってもいいくらい重要な基礎になります。

実際、エンジニアの方々も、一日に何十回、何百回とSELECT文を書いています。それくらい頻繁に使う、データベース操作の基本中の基本なんです。

では、この基本形を踏まえて、次はもう少し実践的な使い方に進んでいきましょう。

## 3-2. WHEREで条件を絞る(15分)

さて、SELECT文の基本形を理解したところで、次はもっと実用的な使い方を見ていきます。

先ほどのSQLは「全部のデータをください」という命令でしたね。でも実務では、全部じゃなくて「特定の条件に当てはまるデータだけ」が欲しいことの方が圧倒的に多いんです。

たとえば、こんな状況を想像してください。

あなたの会社の顧客データベースには、全国のお客様の情報が入っています。北は北海道から南は沖縄まで、何万人ものお客様のデータがある。でも今日、石川県限定のキャンペーンの案内を送ることになりました。だから「石川県に住んでいるお客様だけ」のリストが欲しい。全国のお客様全員のリストじゃなくて、石川県だけ。

そういうときに使うのが「WHERE句」です。

WHEREは英語で「どこ」という意味ですが、SQL では「条件」を指定する部分として使われます。「どこの」データが欲しいか、「どんな」データが欲しいか、を指定する部分だと考えてください。

では、具体例を見てみましょう。

```sql
SELECT *
FROM customers
WHERE prefecture = '石川県';
```

新しく「WHERE prefecture = '石川県'」という一行が追加されましたね。これを日本語で読むと「customersテーブルから、全部の列を取得する。ただし、prefectureカラムの値が『石川県』のデータだけに限定して」という意味になります。

ここでのポイントは3つあります。

1つ目は「WHERE」という単語が、条件を指定する合図になっているということ。WHEREが出てきたら「ああ、何か条件があるんだな」「フィルターがかかっているんだな」と理解してください。

2つ目は「prefecture = '石川県'」という書き方。イコール記号を使って「prefectureというカラムの値が、石川県と等しい」という条件を表現しています。これは数学の等式とほぼ同じ考え方ですね。「prefecture という変数が石川県という値と等しい」というイメージです。

3つ目は、文字列を指定するときに「シングルクォーテーション」で囲んでいるということ。この一重引用符ですね。石川県という文字列を ' で挟んで '石川県' と書いています。これは SQL の決まりで、文字列を扱うときは必ずクォーテーションで囲む必要があるんです。もし囲まずに石川県とだけ書いてしまうと、データベースは「石川県というカラム名か何かかな?」と勘違いしてしまって、「そんなカラムないよ」とエラーになります。

この「文字列はクォーテーションで囲む」というルールは、最初は忘れやすいんですが、何度か使っているうちに自然と身につきます。そして、もし忘れてエラーが出ても、エラーメッセージを見れば「ああ、クォーテーション忘れたな」とすぐわかるようになります。

このSQLを実行すると、結果として返ってくるのは石川県のお客様のデータだけです。東京都のお客様も、大阪府のお客様も、すべて除外されて、石川県だけに絞られた状態で表示されるわけです。

Excelで作業したことがある方なら、フィルター機能をイメージしてもらえると分かりやすいと思います。都道府県の列にフィルターをかけて「石川県だけ表示」と設定する、あの感じです。SQLのWHERE句は、まさにそのフィルター機能を文章で表現したものなんです。

Excelのフィルターと違うのは、SQLは「文章で条件を書く」という点です。マウスでポチポチ選ぶのではなく、言葉で「prefecture = '石川県'」と書く。この「言葉で表現する」というのが、最初は慣れないかもしれませんが、慣れてくると非常に便利なんです。なぜなら、複雑な条件でも文章で表現できますし、その条件をAIに説明するのも簡単だからです。

では、次の例を見てみましょう。今度は日付で絞り込んでみます。

```sql
SELECT *
FROM customers
WHERE created_at >= '2025-11-01';
```

今回は「created_at」というカラムを条件に使っています。これは「登録日時」を表すカラム名だと思ってください。「created」は「作成された」、「at」は「〜に」という意味ですから、「いつ作成されたか」つまり「いつ登録されたか」を記録しているカラムです。

そして条件は「>= '2025-11-01'」。

この「>=」という記号、見たことありますか? これは「以上」という意味です。つまり「2025年11月1日以上」「2025年11月1日か、それより後」という意味になります。数学でも使う記号ですね。

日本語で読むと「customersテーブルから全部の列を取得する。ただし、created_atが2025年11月1日以降のデータだけに限定して」となります。

つまり、このSQLは「今月登録されたお客様」を取得する命令なんです。10月以前に登録されたお客様は除外されて、11月1日以降に登録された新しいお客様だけがリストアップされるわけですね。

「新規登録者を確認したい」「最近増えた顧客の傾向を見たい」といったときに、よく使うパターンです。

ここで使った「>=」のような記号を「比較演算子」と呼びます。少し難しそうな名前ですが、要するに「値を比べるための記号」です。簡単に整理しておきましょう。

- 「=」は「等しい」
- 「!=」または「<>」は「等しくない」
- 「>」は「より大きい」「より後」
- 「<」は「より小さい」「より前」
- 「>=」は「以上」
- 「<=」は「以下」

数学で使う記号とほぼ同じですね。日付や数字を比較するときに、これらの記号を使い分けます。

たとえば「金額が1万円より大きい」なら「amount > 10000」、「年齢が20歳以下」なら「age <= 20」、「登録日が2025年10月31日より前」なら「created_at < '2025-10-31'」という具合です。

この比較演算子も、完璧に覚える必要はありません。使っているうちに自然と身につきますし、迷ったら「以上って >= だっけ?」とAIに聞けばすぐ教えてくれます。

では、もう少し複雑な条件にも挑戦してみましょう。「複数の条件を同時に満たすデータが欲しい」というケースです。

たとえば「石川県に住んでいて、かつ、11月以降に登録されたお客様」が欲しいとします。つまり、2つの条件を両方とも満たす必要がある。そういうときは「AND」という言葉を使って条件を繋げます。

```sql
SELECT *
FROM customers
WHERE prefecture = '石川県'
  AND created_at >= '2025-11-01';
```

ANDは英語で「そして」という意味ですね。SQLでも全く同じ使い方です。「prefectureが石川県で、AND、created_atが11月1日以降」という2つの条件を両方とも満たすデータだけが返ってきます。

これを図で考えると分かりやすいです。全顧客の中で、石川県の人たちという円がある。そして、11月以降に登録した人たちという円がある。ANDは、その2つの円が重なっている部分、つまり「石川県で、かつ、11月以降登録」という両方の条件を満たす人だけを取り出すイメージです。

逆に「どちらか一方を満たせばいい」という場合は「OR」を使います。

```sql
SELECT *
FROM customers
WHERE prefecture = '石川県'
  OR prefecture = '富山県';
```

これは「石川県または富山県のお客様」という意味になります。ORは「または」ですね。どちらか一方に該当すれば、結果に含まれます。

先ほどの図で言うと、ORは2つの円の「どちらかに入っていればOK」という感じです。石川県の円に入っている人も、富山県の円に入っている人も、両方とも結果に含まれます。

このようにWHERE句では、単純な条件だけでなく、ANDやORを使って複雑な条件を組み立てることもできるんです。

さらに、ANDとORを組み合わせることもできます。たとえば、

```sql
SELECT *
FROM customers
WHERE (prefecture = '石川県' OR prefecture = '富山県')
  AND created_at >= '2025-11-01';
```

このようにカッコを使って「石川県または富山県のいずれかで、かつ、11月以降に登録」という条件を表現できます。カッコがあることで「まず石川県または富山県を判定して、その結果と11月以降という条件をANDで結合する」という順序が明確になります。

ただし、条件が複雑になりすぎると、自分で書くのは大変ですし、間違える可能性も高くなります。そういうときこそAIの出番です。

たとえば、こんなふうにAIに依頼してみましょう。画面にプロンプトの例を表示しますね。

```
顧客テーブル customers があり、
prefecture カラムで都道府県、
created_at カラムで登録日を管理しています。

「石川県在住で、2025年10月以降に登録された顧客だけを
取得する SQL」を書いてください。
```

このように、テーブル名とカラム名、そして「何がしたいか」を日本語で説明してあげれば、AIは適切なSQLを返してくれます。

実際にAIが返してきたSQLがこちらです。

```sql
SELECT *
FROM customers
WHERE prefecture = '石川県'
  AND created_at >= '2025-10-01';
```

完璧ですね。私たちが先ほど学んだ形と同じです。WHEREで2つの条件をANDで繋いでいます。

ここで大事なのは、AIが返してきたSQLを「なんとなく読める」ようになることです。完璧に暗記する必要はありません。でも「ああ、WHERE句で条件を指定しているんだな」「ANDで2つの条件を繋いでいるんだな」「prefecture と created_at という2つのカラムを使っているんだな」という構造が分かれば、それで十分なんです。

そして、もしAIが返してきたSQLが意図と違っていたら「prefecture じゃなくて city で絞りたいです」とか「10月じゃなくて11月からにしてください」と指摘すればいい。AIはすぐに修正してくれます。

このように、SQLを完璧に書ける必要はないんです。重要なのは「こういう条件でデータを絞りたい」という要求を日本語で整理できることと、AIが返してきたSQLの意図を読み取れることです。

もう一つ例を見てみましょう。今度は「金額が1万円以上の注文」を取り出すケースです。

```sql
SELECT *
FROM orders
WHERE amount >= 10000;
```

今回は「orders」という注文テーブルを対象にしています。そして「amount >= 10000」という条件。amountは金額ですね。1万円以上という条件を指定しています。

ここで気づいたことはありませんか? 数字にはクォーテーションを付けていませんね。先ほど「石川県」という文字列を指定したときは ' で囲みましたが、数字の場合は囲まないんです。

これもSQLのルールです。文字列は ' で囲む、数字は囲まない。日付も文字列として扱うので ' で囲みます。このルールを覚えておくと、エラーを減らせます。

ちなみに、もし数字を ' で囲んでしまうとどうなるか。多くの場合、データベースが自動的に「これは数字のつもりだろう」と解釈してくれるんですが、厳密には良くない書き方です。そして、場合によってはエラーになることもあります。ですから、数字は ' で囲まない、というルールを頭の片隅に置いておいてください。

ただし、これも完璧に暗記する必要はありません。もし間違えてエラーが出ても、エラーメッセージをAIに貼り付けて「どこが間違っていますか?」と聞けば、すぐに教えてくれますから。

さて、WHERE句についてここまで説明してきましたが、もう少し実務的な例をいくつか見ておきましょう。

たとえば「メールアドレスが登録されていない顧客」を探したいとします。つまり、emailカラムの値が空欄、NULL（ヌル）と呼ばれる状態のデータです。

```sql
SELECT *
FROM customers
WHERE email IS NULL;
```

「IS NULL」という書き方で「値が入っていない」という条件を表現します。逆に「値が入っている」場合は「IS NOT NULL」と書きます。

```sql
SELECT *
FROM customers
WHERE email IS NOT NULL;
```

これで「メールアドレスが登録されている顧客だけ」を取得できます。

NULLというのは「データがない」「未入力」「不明」といった状態を表す特別な値です。0（ゼロ）や空文字列("")とも違う、「何もない」という状態なんです。この概念は最初は少しわかりにくいかもしれませんが、「IS NULL で未入力をチェックできる」ということだけ覚えておけば、実務では十分です。

また、「部分一致」で検索したい場合もあります。たとえば「名前に『田中』が含まれる顧客」を探したい。そういうときは「LIKE」という演算子を使います。

```sql
SELECT *
FROM customers
WHERE name LIKE '%田中%';
```

「%」という記号は「何でもいい文字」を意味します。つまり「%田中%」は「前に何か文字があってもいいし、後ろに何か文字があってもいいけど、とにかく『田中』が含まれていればOK」という意味になります。

これで「田中太郎」さんも「田中花子」さんも「佐藤田中一郎」さんも、すべてヒットします。

逆に「田中で始まる名前」だけが欲しい場合は「田中%」と書きます。

```sql
SELECT *
FROM customers
WHERE name LIKE '田中%';
```

これだと「田中太郎」「田中花子」はヒットしますが、「佐藤田中一郎」はヒットしません。前に何もついていない、「田中」で始まる名前だけが対象になります。

このLIKE演算子は、検索機能を作るときによく使います。Webサイトの検索ボックスに何か入力すると、その文字を含むデータが表示される、あの機能の裏側では、このLIKEを使ったSQLが動いていることが多いんです。

さて、WHERE句についてここまで説明してきましたが、重要なポイントをまとめましょう。

1. WHEREは条件を指定する部分
2. 「カラム名 = 値」という形で条件を書く
3. 文字列は ' で囲む、数字は囲まない
4. 比較演算子 (=, !=, >, <, >=, <=) で様々な条件を表現できる
5. ANDで「両方とも満たす」、ORで「どちらか満たす」条件を作れる
6. IS NULL / IS NOT NULL で未入力チェックができる
7. LIKE で部分一致検索ができる
8. 複雑な条件はAIに日本語で説明して書いてもらえる

WHERE句は、SELECTと並んでSQLの中で最も重要な部分です。データを「全部取る」だけでなく「必要な分だけ絞り込んで取る」ことができるようになると、データベースの使い方が格段に広がります。

実務では、ほとんどのSELECT文にWHERE句が付いていると言っても過言ではありません。それくらい、条件を指定してデータを絞り込むという作業は頻繁に行われるんです。

皆さんも、日々の業務で「こういう条件のデータが欲しい」と思うことがたくさんあると思います。「今月の売上」「特定の地域の顧客」「期限が過ぎた案件」など。そういった「条件」を、WHERE句を使って表現できるようになると、データベースから必要な情報を自由に取り出せるようになります。

では、この調子で次のステップに進みましょう。次は「並び替え」についてです。

## 3-3. ORDER BYで並び替える(10分)

データを取得したあと、もう一つよく必要になるのが「並び替え」です。

たとえば、顧客リストを取得したとき、登録が新しい順に見たいとか、五十音順で見たいとか、そういうニーズがありますよね。Excelでも並び替え機能はよく使うと思います。「名前の列をクリックして、昇順で並び替え」とか、やったことがあるんじゃないでしょうか。

SQLでも同じように、並び替えができるんです。それを実現するのが「ORDER BY句」です。では、具体例を見てみましょう。

```sql
SELECT *
FROM customers
ORDER BY created_at DESC;
```

新しく「ORDER BY created_at DESC」という部分が追加されましたね。

ORDERは「順序」、BYは「〜によって」という意味です。つまり「created_atカラムの値によって順序を決めてください」という指示になります。

そして最後の「DESC」。これは「Descending」の略で、「降順」という意味です。大きい値から小さい値へ、新しい日付から古い日付へ、という並び方ですね。山を降りていくイメージ、DESCend（下降する）と覚えるといいかもしれません。

このSQLを実行すると、顧客データが「登録日時が新しい順」に並んで返ってきます。つまり、一番最近登録されたお客様が一番上に表示され、古いお客様ほど下に並ぶという状態になります。

「最新の登録者を確認したい」「最近どんな人が登録しているか見たい」というときに、よく使うパターンです。管理画面でユーザー一覧を見るとき、普通は新しい人が上に来る方が便利ですよね。そういう場合にこのORDER BY ... DESCを使います。

では、逆に古い順に並べたい場合はどうするか。その場合は「DESC」の代わりに「ASC」を使います。

```sql
SELECT *
FROM customers
ORDER BY created_at ASC;
```

ASCは「Ascending」の略で、「昇順」という意味です。小さい値から大きい値へ、古い日付から新しい日付へ、という並び方です。山を登っていくイメージ、ASCend（上昇する）ですね。

これを実行すると、登録日時が古い順に並びます。創業当初からのお客様が上に来て、最近のお客様ほど下になります。「顧客番号1番の人は誰だったかな」「一番最初に登録してくれたお客様を確認したい」といったときに使います。

ちなみに、ASCは省略可能です。つまり、

```sql
SELECT *
FROM customers
ORDER BY created_at;
```

とだけ書いても、自動的に昇順になります。でも、読みやすさのために明示的にASCと書いておくことが多いですね。「ああ、昇順で並べているんだな」というのが一目で分かりますから。

では、文字列で並び替える例も見てみましょう。

```sql
SELECT *
FROM customers
ORDER BY name ASC;
```

今回は「name」カラム、つまり名前で並び替えています。ASCなので昇順、つまり五十音順に並ぶことになります。あ行の人が上に来て、わ行の人が下になる、という並びですね。

名簿を作るときなど、五十音順で並べたいことはよくありますから、これも実務でよく使うパターンです。学校の出席簿みたいなイメージですね。

アルファベットの場合も同様で、A、B、C...の順番に並びます。名前が「Aさん」から始まる人が上に、「Zさん」から始まる人が下に並ぶという具合です。

さて、ここで「DESC」と「ASC」の覚え方を一つ。

「A」から始まるASCが「A、B、C...」と小さい順に進んでいくイメージ。「D」から始まるDESCが「大きい方から降りてくる」イメージ。あるいは、「DESCは下降、ASCは上昇」と覚えるのもいいですね。

でも、正直に言うと、これも完璧に暗記する必要はありません。「昇順だっけ降順だっけ?」と迷ったら、その場でAIに聞けばいいんです。あるいは、実際にSQLを実行してみて「あれ、逆だった」となったら、DESC と ASC を入れ替えればいいだけです。

実務では、試しに実行してみて、結果を見て「ああ、逆だった」と気づいて修正する、というのは日常茶飯事です。完璧を目指すより、「やってみて、確認して、必要なら直す」というサイクルを回す方が、よほど効率的です。

さらに、ORDER BYは複数のカラムを指定することもできます。

```sql
SELECT *
FROM customers
ORDER BY prefecture ASC, created_at DESC;
```

これは「まず都道府県の五十音順に並べて、同じ都道府県の中では登録日が新しい順に並べる」という意味になります。

つまり、愛知県のお客様が上に来て、その中で登録が新しい人から順に並び、次に石川県のお客様が来て、また登録が新しい順に並び...という具合です。

カンマで区切って複数の並び替え基準を指定できるんですね。最初の基準で並べて、同じ値の場合は2番目の基準で並べる、という動きになります。

たとえば、営業の方が「都道府県ごとに顧客を見たいけど、各都道府県の中では新しいお客様を優先的に確認したい」といったニーズがあるときに便利です。

ただし、これも複雑になりすぎると混乱しやすいので、実務ではシンプルな並び替えを使うことがほとんどです。2つくらいの基準ならよくありますが、3つ、4つと増えていくと、結果を見ても「どういう順番で並んでいるのか」が分かりにくくなってしまいますから。

では、ここでAIを活用する例を見てみましょう。たとえば、こんなふうに依頼します。

```
顧客テーブル customers から、
石川県の顧客だけを取得し、
created_at(登録日)の新しい順に並べる SQL を書いてください。
```

これまで学んだWHERE句とORDER BY句を組み合わせた依頼ですね。AIはこう返してくれるはずです。

```sql
SELECT *
FROM customers
WHERE prefecture = '石川県'
ORDER BY created_at DESC;
```

完璧です。WHERE句で石川県に絞り込み、ORDER BY句で登録日の降順に並べています。

このSQLを見たときに、皆さんが「ああ、石川県だけ取って、新しい順に並べるんだな」と理解できれば、もうSQLの基本は十分に身についています。

実際、エンジニアの方とコミュニケーションを取るときも、このレベルで読めれば問題ありません。「このSQLで合ってますか?」と確認されたときに、「はい、石川県で絞って、新しい順に並べるんですよね。それで合ってます」と答えられる。それだけで、コミュニケーションは格段にスムーズになります。

ここまでで、SELECT文の3つの重要な要素を学びました。

1. SELECT と FROM で「どのテーブルから、どの列を取るか」を指定
2. WHERE で「どんな条件で絞り込むか」を指定
3. ORDER BY で「どの順番に並べるか」を指定

この3つを組み合わせることで、データベースから「欲しいデータを、欲しい形で」取り出すことができるようになります。

実務でのSQLの大部分は、この3つの組み合わせです。特殊な関数や高度なテクニックもたくさんありますが、非エンジニアの方がまず押さえるべきなのは、この3つの基本構造なんです。

そして繰り返しになりますが、これらを完璧に暗記して自分で書ける必要はありません。重要なのは「こういう条件でデータを取りたい」という要求を日本語で整理できることと、AIが書いたSQLを読んで「ああ、こういう処理をしているんだな」と理解できることです。

では、まとめに入る前に、これまで学んだことを組み合わせた総合例を一つ見ておきましょう。

```sql
SELECT customer_id, name, email, created_at
FROM customers
WHERE prefecture = '石川県'
  AND created_at >= '2025-11-01'
ORDER BY created_at DESC;
```

このSQLは、

- customersテーブルから
- customer_id、name、email、created_atの4列だけを取得し
- prefectureが石川県で、かつ、created_atが2025年11月1日以降という条件で絞り込み
- created_atの新しい順に並べる

という処理をしています。

一行ずつ読んでいくと、

「SELECT customer_id, name, email, created_at」→ この4つの列を取得する
「FROM customers」→ customersテーブルから
「WHERE prefecture = '石川県'」→ 石川県の顧客で
「AND created_at >= '2025-11-01'」→ かつ11月1日以降に登録した人で
「ORDER BY created_at DESC」→ 登録日が新しい順に並べる

という意味になります。

これが読めれば、SQLの基本は完璧です。

実務では、このレベルのSQLが書けたり読めたりするだけで、エンジニアとのコミュニケーションが格段にスムーズになります。「こういうデータが欲しい」と言葉で説明するだけでなく、「このSQLでいいですか?」と具体的に確認できるようになるからです。

そして何より、AIに適切な指示を出せるようになります。「石川県の顧客で、今月登録の人を、新しい順に並べて、ID・名前・メール・登録日だけ取得したい」と日本語で説明すれば、AIがこのSQLを書いてくれるんです。

これが「SQLを書けないけれど、SQLを使いこなせる」という状態です。これからのAI時代に必要なのは、まさにこういうスキルなんですね。

プログラミング言語を完璧にマスターする必要はありません。でも、「何ができるのか」「どういう考え方なのか」を理解していて、AIに適切に指示を出せる。そして、AIが返してきた結果を評価できる。そういう能力が、これからますます重要になっていきます。

さて、SELECT文についてはここまでです。ここまでで、SQLの「読む」という部分、つまりデータを取得する部分の基本は理解できたと思います。

次は INSERT、UPDATE、DELETEという、データを変更する命令について見ていくことになりますが、それはこのパートの後の話です。
