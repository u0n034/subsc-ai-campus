SQLとは
Structured Query Language
「構造化問い合わせ言語」

難しそうな名前ですが、実際には
「データベースへの命令文」
「表データに対するお願いの言葉」
くらいの理解で十分！
📖
SELECT：データを読む
基本の4つのキーワード：

• SELECT：何を取得するか
• FROM：どのテーブルから
• WHERE：どんな条件で
• ORDER BY：どう並べるか

この組み合わせがデータ取り出しの基本パターン
✍️
データを書き込む3つの命令
• INSERT：新しいデータを追加
• UPDATE：既存データを書き換え
• DELETE：データを削除

WHERE句は必須！
ないと全件に影響してしまう
🏷️
論理削除の文化
実務では、データを本当に消すのではなく
「削除フラグ」を立てる方法が主流

• is_deleted = 1
• deleted_at = 削除日時

これにより、必要なときに復旧できる
安全なシステム設計の基本
🐛 エラーへの向き合い方
SQLは、ちょっとしたスペルミスでもエラーになります。
でも、エラーが出ることは「できない証拠」ではなく、
「ここがおかしいよ」というヒントなんです。

エラーメッセージをそのままAIに貼り付けて、
「これはどういう意味ですか？どう直せばいいですか？」と聞けば、
AIがだいたい教えてくれます。
🎯 最も重要なこと
皆さんに求められているのは、
完璧なSQLを書けるようになることではありません

重要なのは：

✅ 「こういうデータが欲しい」という業務上の要求を、
きちんと日本語で言語化できること

✅ それをAIに伝えてSQLに変換してもらい、
エラーが出たらAIと一緒に直していく

このスタンスを持っていれば、
エンジニアとの会話もぐっとスムーズになります

第4回
APIとバックエンドの役割
🌐 次回のテーマ
今日の講座では、SQLを使って
「データベースに対して、データを読んだり書いたりする」という部分に焦点を当ててきました。

でも、実際のWebサービスでは、
皆さんがブラウザやスマホアプリで操作すると、
その裏側でバックエンドがSQLを実行して、データベースとやり取りをしています。

では、フロントエンド（画面側）から、バックエンドに対して
「こういうデータが欲しい」「このデータを保存してほしい」というお願いは、
どうやって届けられているのでしょうか？

その橋渡しをしているのが「API」という仕組みです。
🔌
API
とは何か
🌐
HTTP
の基本
📡
REST
の考え方
📋
JSON
データ形式
🎓 こんなことを学びます
• HTTP：インターネット上でデータをやり取りするときの「約束事」

• REST：APIを設計するときの「お作法」の一つ

• GET / POST：「データをください」と「データを送ります」の違い

• JSON：{ "name": "田中", "age": 35 } というデータの表現方法
  人が読んでも分かりやすく、機械も処理しやすいので、APIでよく使われる

今日学んだ「SQLでデータを読む・書く」という処理を、
フロントエンドからどうやって呼び出すのか、という視点で
全体像を見ていくことで、
バックエンドとデータベースとフロントエンドの関係が、
より立体的に理解できるようになります。
🤖 もちろん、次回もAIを活用！ 「自分で難しいコードを書かなきゃいけないのかな」という心配は無用です。

AIに「顧客管理システムのAPI一覧を提案して」と依頼して、
どんな答えが返ってくるのかを一緒に見ていく、
というスタイルで進めていきます。
