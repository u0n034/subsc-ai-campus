# 第3回 セクション5「よくあるエラーとAIに直してもらう流れ」ナレーション原稿

## 5-1. ありがちなエラー例(7分)

それでは、SQLを書く上で「よくあるエラー」について見ていきましょう。

ここまで、SELECTでデータを読んだり、INSERT、UPDATE、DELETEでデータを操作する基本的な流れをご紹介してきました。ただ、実際に手を動かしてみると、「あれ、エラーが出た」という場面に必ず遭遇します。

でも、安心してください。**エラーが出るのは、決して「自分にはできない」という証拠ではありません**。むしろ、「ここがちょっとおかしいですよ」とコンピュータが教えてくれているヒントなんです。

プログラミングやSQLに慣れている人でも、毎日のようにエラーと向き合っています。大切なのは、**エラーを恐れずに、「何が原因なのか」を読み解く姿勢**です。

そして今の時代、私たちにはAIという心強い味方がいます。エラーメッセージをAIに見せて、「これはどういう意味ですか?」「どう直せばいいですか?」と聞くことで、かなりの部分が解決できるんです。

それでは、SQLでよく起こる典型的なエラーパターンを3つご紹介します。画面には、それぞれのパターンを表示していますので、一緒に見ていきましょう。

---

**【パターン1:カラム名のスペルミス】**

まず一つ目は、**カラム名のスペルミス**です。

たとえば、都道府県を表す「prefecture」というカラムがあったとします。これを「prefecturee」と、最後にeを一つ多く付けてしまったらどうなるでしょうか。

```sql
SELECT *
FROM customers
WHERE prefecturee = '石川県';
```

このSQLを実行すると、データベースから次のようなエラーメッセージが返ってきます。

```
column "prefecturee" does not exist
```

直訳すると、「prefectureという名前のカラムは存在しません」という意味ですね。

SQLは、**一文字でも違うと、まったく別のものとして認識してしまいます**。人間の目で見ると「だいたい合ってるじゃん」と思えるようなミスでも、コンピュータは融通を利かせてくれないんです。

日本語入力と英語入力を切り替えているときに、うっかり全角で入力してしまったり、大文字小文字を間違えたりすることもあります。SQLでは基本的に大文字小文字は区別されませんが、カラム名やテーブル名の設定によっては区別されることもあるので、注意が必要です。

---

**【パターン2:シングルクォートの付け忘れ・抜け】**

二つ目は、**シングルクォート(')の付け忘れや抜け**です。

SQLでは、文字列を扱うときには必ず「シングルクォート」で囲む必要があります。たとえば、

```sql
SELECT *
FROM customers
WHERE prefecture = '石川県';
```

この「'石川県'」の部分ですね。

もしこれを、

```sql
WHERE prefecture = 石川県
```

と書いてしまうと、データベースは「石川県」という文字列ではなく、「石川県」という名前のカラムを探そうとしてしまいます。当然そんなカラムは存在しないので、エラーになってしまうわけです。

また、シングルクォートを閉じ忘れて、

```sql
WHERE prefecture = '石川県
```

と書いてしまうと、「文字列がどこまで続くのか分からない」という構文エラーになります。

これは初心者の方が特に引っかかりやすいポイントです。**数値はそのまま書けるけれど、文字列はクォートで囲む**。この違いをしっかり意識しておきましょう。

---

**【パターン3:セミコロン(;)の付け忘れ】**

三つ目は、**セミコロン(;)の付け忘れ**です。

SQLでは、一つの命令の終わりを示すために、文末にセミコロンを付けるのが基本です。

```sql
SELECT * FROM customers;
```

このセミコロンがないと、データベースによっては「まだ命令が続くのかな?」と待ち続けてしまったり、エラーを返してきたりします。

特に、複数のSQL文を連続で実行するときには、セミコロンがないと、どこまでが一つの命令なのか判断できなくなってしまいます。

ただし、ツールや環境によっては、セミコロンがなくても実行できる場合もあります。でも、**書く習慣を付けておいた方が、後々のトラブルを避けられます**。

---

この3つのエラーパターン、いかがでしょうか。

「なんだ、そんな細かいこと?」と思われるかもしれませんね。でも実際、SQLを書いているときのエラーの大半は、こういった**タイプミスや記号の抜け**なんです。

エンジニアでも、何年も経験を積んでいる人でも、こういったミスは日常茶飯事です。だからこそ、**エラーが出たときに慌てない**こと、そして**エラーメッセージをしっかり読む**ことが大切なんです。

エラーメッセージは、一見すると英語ばかりで難しそうに見えますが、よく見ると「ここがおかしいよ」というヒントが必ず書かれています。

たとえば先ほどの「column "prefecturee" does not exist」というメッセージなら、「prefectureeというカラムがない」と言っているわけですから、「あ、カラム名を間違えたかな」と気づくきっかけになります。

最初は英語のメッセージを読むのが大変かもしれませんが、何度か見ているうちに、だんだんパターンが分かってきます。そして、**AIに助けてもらえば、このハードルは一気に下がります**。

それでは次に、実際にAIにエラーの意味を聞いて、直してもらう流れを見ていきましょう。

---

## 5-2. AIにエラーの意味を聞いてみるデモ(8分)

それでは、実際にエラーが出たときに、**AIにどうやって相談すればいいのか**、具体的な流れをお見せします。

ここでは、先ほど紹介した「カラム名のスペルミス」を例にして、AIとのやり取りをデモンストレーションしていきますね。

---

**【ステップ1:わざとエラーを起こす】**

まず、わざとエラーが出るSQLを書いて実行してみます。

```sql
SELECT *
FROM customers
WHERE prefecturee = '石川県';
```

「prefecture」を「prefecturee」と、eを一つ多く書いてしまいました。

これを実行すると、画面にはこんなエラーメッセージが表示されます。

```
ERROR: column "prefecturee" does not exist
LINE 3: WHERE prefecturee = '石川県';
              ^
```

英語でエラーが出てくると、ちょっとドキッとしますよね。でも、落ち着いて見てみましょう。

「column "prefecturee" does not exist」つまり、「prefectureというカラムは存在しない」と言っています。

そして「LINE 3」というのは、3行目に問題があるということ。さらに「^」マークで、どの部分がおかしいのかを指し示してくれています。

このエラーメッセージ、実は**かなり親切に教えてくれている**んです。ただ、慣れていないとピンとこないかもしれませんね。

そこで、このエラーメッセージを丸ごとAIに投げてみましょう。

---

**【ステップ2:エラー全文をAIにコピー&ペースト】**

それでは、エラーメッセージを全部選択して、コピーします。

そして、ChatGPTやClaudeなどのAIツールを開いて、次のように質問してみます。

```
次のSQLを実行したところ、エラーが出ました。

SQL:
SELECT *
FROM customers
WHERE prefecturee = '石川県';

エラー内容:
ERROR: column "prefecturee" does not exist
LINE 3: WHERE prefecturee = '石川県';
              ^

エラーの意味と、どう直せばいいか教えてください。
```

ポイントは、**SQLとエラー内容の両方をセットで伝える**ことです。

SQLだけを見せても、エラーだけを見せても、AIは正確な判断ができません。「こういうSQLを書いたら、こういうエラーが出た」という文脈を一緒に渡すことで、AIがより的確なアドバイスをしてくれます。

---

**【ステップ3:AIからの回答を読む】**

すると、AIからこんな回答が返ってきます。

```
エラーの意味:
「prefecturee」という名前のカラムが存在しないというエラーです。
おそらく、カラム名のスペルが間違っている可能性があります。

修正案:
正しいカラム名は「prefecture」だと思われますので、
次のように修正してください。

SELECT *
FROM customers
WHERE prefecture = '石川県';

確認事項:
もし「prefecture」でもエラーが出る場合は、
テーブル「customers」に実際にどんなカラムがあるのか、
以下のSQLで確認してみてください。

SELECT column_name
FROM information_schema.columns
WHERE table_name = 'customers';
```

いかがでしょうか。

AIは、**エラーの原因を分かりやすく説明**してくれて、**修正したSQLまで書いてくれました**。さらに、「それでもダメだったら、こうやって確認してみて」という次の手まで提案してくれています。

これ、すごく心強いですよね。

エンジニアに質問するのは気が引ける、という方もいらっしゃるかもしれません。でも、AIなら24時間いつでも、何度聞いても嫌な顔一つせずに答えてくれます。

---

**【ステップ4:修正したSQLを実行してみる】**

それでは、AIが提案してくれた修正版のSQLを実行してみましょう。

```sql
SELECT *
FROM customers
WHERE prefecture = '石川県';
```

今度はエラーが出ず、無事に結果が表示されました!

画面には、石川県に住んでいる顧客のデータがズラッと並んでいます。

これで、**エラーの原因を突き止めて、正しく修正することができました**。

---

**【別パターン:シングルクォート抜けのケース】**

もう一つ、別のエラーパターンも見てみましょう。

今度は、シングルクォートを付け忘れた場合です。

```sql
SELECT *
FROM customers
WHERE prefecture = 石川県;
```

これを実行すると、こんなエラーが出ます。

```
ERROR: column "石川県" does not exist
```

「石川県」というカラムが存在しない、と言われてしまいました。

このエラーメッセージだけ見ると、「え、石川県って書いたのに、何でダメなの?」と混乱するかもしれません。

でも、ここでもAIに聞いてみましょう。

```
次のSQLでエラーが出ました。

SQL:
SELECT *
FROM customers
WHERE prefecture = 石川県;

エラー:
ERROR: column "石川県" does not exist

どう修正すればいいですか?
```

すると、AIはこう答えてくれます。

```
エラーの原因:
「石川県」が文字列として認識されず、カラム名として
扱われてしまっています。

修正方法:
文字列はシングルクォート(')で囲む必要があります。
次のように修正してください。

SELECT *
FROM customers
WHERE prefecture = '石川県';

SQLでは、数値はそのまま書けますが、
文字列は必ずシングルクォートで囲むというルールがあります。
```

完璧ですね!

AIは、**なぜエラーが起きたのか**を説明してくれて、**どう直せばいいのか**を具体的に教えてくれました。

---

**【このやり方の素晴らしいところ】**

このように、エラーが出たときに「SQL + エラーメッセージ」をセットでAIに投げることで、ほとんどの場合は解決のヒントが得られます。

このやり方の素晴らしいところは、**自分でSQLの文法を完璧に覚えていなくても大丈夫**という点です。

もちろん、基本的な構造を理解しておくことは大事です。でも、細かいルールやスペルまで全部暗記する必要はありません。

**「やりたいこと」を日本語で整理できていれば、AIがそれをSQLに変換してくれます**。

そして、もしエラーが出たら、**AIに「これ、どういう意味?」と聞けばいい**んです。

これが、AI時代の学び方の新しいスタイルだと思います。

---

**【注意点:AIも完璧ではない】**

ただし、一つだけ注意点があります。

AIも万能ではありません。時には、間違った提案をしてくることもあります。

特に、テーブル構造やカラム名が特殊な場合、AIが推測で答えることもあります。

ですから、**AIの回答を鵜呑みにせず、実際に試してみる**ことが大切です。

そして、もしAIの提案でもうまくいかない場合は、もう一度AIに「これでもダメでした」と伝えて、別の角度から提案してもらいましょう。

AIとの対話は、一回で終わりではありません。**何度かやり取りをしながら、正解に近づいていく**プロセスなんです。

---

**【実務での活用イメージ】**

最後に、実務でこの方法をどう活かせるか、少しイメージしてみましょう。

たとえば、あなたが社内のデータベースから「今月登録された顧客の一覧が欲しい」と思ったとします。

エンジニアに頼むほどでもないけど、自分でサッと取り出せたら便利ですよね。

そんなとき、まずAIに「こういうデータが欲しいんですが、SQLを書いてください」とお願いします。

AIがSQLを返してくれたら、それをコピーして実行してみる。

もしエラーが出たら、エラーメッセージをまたAIに見せて直してもらう。

この流れを何回か繰り返すうちに、**自分でもSQLの感覚が掴めてきます**。

そして、「あ、このパターンは前にも見たな」「ここはこういうルールだったな」と、少しずつ理解が深まっていきます。

最初から完璧を目指す必要はありません。**AIと一緒に試行錯誤しながら、徐々に慣れていけばいい**んです。

---

**【まとめ】**

1. SQLでよくあるエラーは、「カラム名のスペルミス」「クォートの付け忘れ」「セミコロンの抜け」など、細かいミスがほとんど

2. エラーメッセージは怖くない。「ここがおかしいよ」というヒントが書かれている

3. エラーが出たら、「SQL + エラーメッセージ」をセットでAIに投げる

4. AIが原因と修正方法を教えてくれるので、それを試してみる

5. 完璧に覚える必要はなく、AIと一緒に試行錯誤しながら学んでいく

この「AIに助けてもらいながらエラーを直す」という経験を積むことで、**エラーへの恐怖心がなくなり、自信を持ってSQLに向き合えるようになります**。
