

# ②「AIエージェントと高度な自動化」8時間（2時間×4）

※ここはツールを固定しすぎず、

* OpenAI / Anthropic などのLLM API
* n8n（ツール呼び出し）や Dify・自作エージェント
  などを例に、**概念＋実務パターン**を押さえるコースにしています。

## コースコンセプト

* **対象**

  * 「ワークフロー自動化とAPI連携」レベルはざっくり理解している人
  * LLMを「ただのチャット」から「業務代行エージェント」に格上げしたい人
* **ゴール**

  * エージェントと通常のチャットボットの違いを説明できる
  * 「ツール実行」「メモリ」「マルチステップ思考」の要素を理解
  * 調査・要約・定型オペレーションなど、**自社で使えそうなエージェントのユースケースを設計できる**
  * 実務に耐えうるための「人間の最終チェック」やガードレールの考え方がわかる

## 第1回：AIエージェントとは何か？概念とアーキテクチャ（2h）

**狙い：**「エージェントって結局何？」を整理し、技術詳細よりも**設計視点**を持つ。

1. チャットボットとエージェントの違い（30分）

   * チャットボット：質問→回答で完結
   * エージェント：

     * 目的を受け取る
     * 自分でタスクを分解
     * 必要に応じてツールやAPIを呼び出す
   * 例：

     * 「◯月の売上レポートを作って」→DB参照→集計→レポート文章

2. エージェントの基本構成要素（30分）

   * LLM（頭脳）
   * ツール（API・DB・ワークフロー）
   * メモリ（会話履歴・長期記憶）
   * オーケストレーター（n8n/Dify/自作アプリ など）

3. 簡易エージェントのデモ構成を解説（30分）

   * 「問い合わせメールを分類→担当者ごとにSlackへ送信」など
   * LLMは「分類」と「メッセージ作成」だけ担当させる

4. 自社に合いそうなエージェント案出し（25分）

   * 例：

     * 日報要約エージェント
     * 営業アポ候補日の提案エージェント
     * お問い合わせ返信案作成エージェント
   * 3案ほど洗い出し、「狙い」と「使うデータ源」を整理

5. まとめ（5分）

## 第2回：調査・要約エージェント – 情報収集の半自動化（2h）

**狙い：**調査・要約・レポート作成をエージェントに任せるパターンを理解する。

1. 調査・要約系タスクの棚卸し（20分）

   * 例：

     * 業界ニュースの収集
     * 競合サイトの比較
     * アンケート結果の要約
   * 「自分で毎回やっている調査系作業」を書き出す

2. 調査エージェントの基本フロー（40分）

   * (1) テーマと粒度を受け取る
   * (2) Web/APIから情報収集
   * (3) 要約・分類・抜粋
   * (4) レポート形式に整形
   * ツール例：

     * n8nでHTTPリクエスト→LLM要約→Google Docs / Notion へ保存
     * Difyの「エージェント + ツール」構成 など

3. プロンプト設計のポイント（40分）

   * 情報ソースの制限（どこまで信頼するか）
   * 出力フォーマット固定（箇条書き／表／テンプレ）
   * 「ハルシネーション対策」として

     * 自信がないときは「不明」と回答させる
     * 根拠URLを必ず添付させる 等

4. ミニワーク：自社向け「ニュースダイジェスト」エージェント案（20分）

   * 目的・入力・出力・頻度・使うツールをざっくり設計

---

## 第3回：オペレーション自動化エージェント – 実行系タスク（2h）

**狙い：**「調査だけでなく、実際に何かを“動かす”エージェント」のイメージを掴む。

1. 実行系タスクの例出し（20分）

   * カレンダー登録・タスク管理ツールへの登録・Slack送信・メール送信など
   * 「人間のクリックを代わりにやる」イメージ

2. エージェント＋ワークフローの組み合わせ（40分）

   * 例パターン：

     * LLM：入力文の解釈・構造化
     * n8n：構造化されたデータを受け取ってAPI実行
   * 「エージェントが全部やる」のではなく、
     **“命令書を作るAI”＋“実行するn8n”** の役割分担を解説

3. 人間の承認フロー（Human-in-the-loop）（40分）

   * 例：

     * LLMが「メール下書き」を作成 → Slackに投げる → 人がOKしたらn8nが送信
   * 誤送信・誤操作の防止策
   * ログ・履歴の残し方の考え方

4. ミニワーク：
   「毎週のルーティン業務をエージェント＋n8nでどこまで自動化できるか？」（20分）

   * 1つの業務について、

     * AIに何をさせるか
     * n8nに何をさせるか
       を分けて整理

## 第4回：自社向けAIエージェント設計と運用設計（2h）

**狙い：**「技術的にできそう」から一歩進めて、「実際に回すとしたら？」を設計する。

1. 自社向けエージェント候補の絞り込み（30分）

   * これまで出てきた案の中から「1〜2本」に絞る
   * 選定基準：

     * 頻度が高い
     * ミスの影響が小さい
     * 成果が社内でわかりやすい

2. アーキテクチャラフ設計（40分）

   * どのツールを使うか（LLM、n8n、既存SaaS）
   * データの入り口／出口（フォーム、スプレッドシート、チャットなど）
   * 失敗時のハンドリング（どこに通知？誰が見る？）

3. KPIとリスク・ルールの整理（30分）

   * KPI例：

     * 月◯時間の削減
     * レポート作成時間の◯％削減
   * リスク例：

     * 誤情報の自動送信
     * 個人情報の扱い
   * 運用ルール例：

     * 「最初の1ヶ月は人間の承認必須」
     * 「重要メールは下書きまでで自動送信しない」

4. 「エージェント企画書」たたき台作成（15分）

   * 構成：目的／対象業務／使用ツール／フロー図／KPI／リスクと対策
   * 社内の上長・経営陣に説明できるレベルのドキュメント

5. クロージング（5分）
